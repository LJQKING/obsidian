**MMKV** 是微信团队开源的一款专为移动端（现已支持 Android、iOS、macOS、Windows、POSIX、HarmonyOS 等多平台）设计的高性能**键值存储（Key-Value）组件**，用来替代传统的 `SharedPreferences` (Android) 或 `NSUserDefaults` (iOS)。

### 一、 MMKV 的核心底层原理

MMKV 性能极高（通常比 SharedPreferences 快数倍甚至数十倍），其核心设计原理主要包含以下三点：

1. **内存映射 `mmap`（Memory Mapping）**
    
    - **原理**：传统的文件读写（IO）需要经历从用户态拷贝到内核态、再写入磁盘的过程。MMKV 利用操作系统的 `mmap` 技术，将一个物理文件直接映射到进程的虚拟地址空间。
        
    - **优势**：读写内存就等于读写文件，避免了内核态与用户态之间频繁的数据拷贝；同时，即使 App 发生了崩溃（Crash）或被强杀，操作系统也会负责将 `mmap` 缓冲区的数据刷新写回磁盘，极大地保障了数据不丢失。
        
2. **Protocol Buffers 序列化（Protobuf）**
    
    - **原理**：MMKV 采用改进版 Protobuf 编码格式来对 Key-Value 数据进行序列化。
        
    - **优势**：Protobuf 生成的二进制数据体积极小，序列化与反序列化速度极快。
        
3. **增量更新与增量重构（Incremental Updates）**
    
    - **原理**：每次写入新的数据时，MMKV 不会像传统存储一样把整个文件重新序列化全量重写，而是**直接把新变更的数据 append（追加）到文件末尾**。
        
    - **清理**：当 append 到文件空间不足时，MMKV 才会在内存中做一次去重整合，并将整合后的全量数据重新写回文件（文件重构）。
        

### 二、 在 Android 中使用 MMKV 示例

#### 1. 引入依赖

在 `build.gradle` 中添加依赖：

Groovy

```
dependencies {
    implementation 'com.tencent:mmkv:1.3.9' // 请根据官方版本调整
}
```

#### 2. 初始化（在 Application 的 onCreate 中调用）

Kotlin

```
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        // 初始化 MMKV
        MMKV.initialize(this)
    }
}
```

#### 3. 基础读写操作

MMKV 提供了类似于 `SharedPreferences` 的极简接口，但写入是**同步写入内存（实时生效），异步靠 mmap 落盘**，不需要手动调用 `apply()` 或 `commit()`：

Kotlin

```
// 获取默认实例
val kv = MMKV.defaultMMKV()

// 写入数据（直接调用 encode，立刻生效）
kv.encode("user_id", 123456)
kv.encode("user_name", "Alex")
kv.encode("is_vip", true)

// 读取数据（如果不存在，返回默认值）
val userId = kv.decodeInt("user_id", 0)
val userName = kv.decodeString("user_name", "")
val isVip = kv.decodeBool("is_vip", false)

// 删除数据
kv.removeValueForKey("user_name")
```

### 三、 MMKV 与 Jetpack DataStore 的对比

Google 推出的 **Jetpack DataStore**（包含 Preferences DataStore 和 Proto DataStore）是用来替代 SharedPreferences 的官方库。下表总结了它们的核心差异：

|**对比维度**|**MMKV**|**Jetpack DataStore**|
|---|---|---|
|**开发背景**|腾讯微信团队开源|Google Android 官方团队出品|
|**底层实现**|C++ 核心，基于 `mmap` + 自定义 Protobuf 追加写入|基于 Kotlin 协程 / Flow + 文件本地全量 IO 写入|
|**读写性能**|**极高**（直接操作 `mmap` 映射内存，几乎没有 IO 开销）|**中等**（虽然优于 SP，但仍有序列化和文件 IO 成本）|
|**API 调用形式**|**同步 API**（简单直观，类似 `kv.decodeString()`）|**异步/响应式 API**（依赖 Kotlin Coroutines/Flow）|
|**主线程阻塞风险**|极低（写入内存映射区，耗时通常为微秒级）|完全避免（强制在非 UI 线程异步执行）|
|**多进程支持**|原生高效支持多进程互斥 lock|1.1.0+ 支持 `MultiProcessDataStore`，但机制相对较重|
|**跨平台支持**|支持 Android, iOS, Windows, macOS, OHOS 等|现支持 Android, Kotlin MultiPlatform (KMP)|

#### 总结选型建议：

1. **选择 MMKV 的场景：**
    
    - **追求极致性能**：比如需要频繁读写 KV、启动阶段要同步阻塞读取大量配置信息等。
        
    - **代码库迁移平滑**：需要快速替代现有的 `SharedPreferences`，且不想大幅重构原有的同步调用逻辑。
        
    - **多平台/多进程需求**：需要跨平台（如 iOS 和 Android 共用逻辑）或存在复杂的多进程协同读写。
        
2. **选择 DataStore 的场景：**
    
    - **全 Kotlin/Compose 生态**：项目深度使用 Kotlin 协程和 Flow 响应式架构，希望数据流天生具有响应能力（Observation）。
        
    - **纯官方原生依赖**：团队限制使用第三方 C/C++ 动态链接库（so 文件），希望尽量降低 APK 体积。
        
    - **类型安全（Proto DataStore）**：需要使用严谨的 Schema 定义复杂的数据结构并进行强类型检查。
