## 二、ThreadPoolExecutor 源码详解

### 2.1 核心数据结构

```java
// ThreadPoolExecutor.java (JDK)
public class ThreadPoolExecutor extends AbstractExecutorService {
    
    // 原子变量：状态 + 工作线程数（32位状态 + 32位计数）
    private final AtomicInteger ctl = new AtomicInteger(ctlOf(RUNNING, 0));
    private static final int COUNT_BITS = Integer.SIZE - 3; // 29
    private static final int COUNT_MASK = (1 << COUNT_BITS) - 1; // 掩码
    
    // 线程池状态（高3位）
    private static final int RUNNING    = -1 << COUNT_BITS;  // 11100000...
    private static final int SHUTDOWN   =  0 << COUNT_BITS;  // 00000000...
    private static final int STOP       =  1 << COUNT_BITS;  // 00100000...
    private static final int TIDYING    =  2 << COUNT_BITS;  // 01000000...
    private static final int TERMINATED =  3 << COUNT_BITS;  // 01100000...
    
    // 关键参数
    private final int corePoolSize;
    private final int maximumPoolSize;
    private final long keepAliveTime;
    private final TimeUnit unit;
    
    // 工作线程集合与阻塞队列
    private final HashSet<Worker> workers = new HashSet<>();
    private final BlockingQueue<Runnable> workQueue;
    
    // 拒绝策略
    private volatile RejectedExecutionHandler handler;
    private volatile ThreadFactory threadFactory;
}

// 状态解码方法
private static int runStateOf(int c)     { return c & ~COUNT_MASK; }
private static int workerCountOf(int c)  { return c & COUNT_MASK; }
private static int ctlOf(int rs, int wc) { return rs | wc; }
```

**关键设计**：

- ctl 使用**原子变量**同时存储线程池状态和工作线程数，避免竞态条件
- 高3位表示状态，低29位表示工作线程数
- 状态转移：RUNNING → SHUTDOWN → STOP → TIDYING → TERMINATED

### 2.2 Worker 内部类（线程包装器）

```java
private final class Worker extends AbstractQueuedSynchronizer 
    implements Runnable {
    
    final Thread thread;  // 关联的真实线程
    Runnable firstTask;   // 第一个任务
    volatile long completedTasks;
    
    Worker(Runnable firstTask) {
        setState(-1); // 初始化状态，防止中断
        this.firstTask = firstTask;
        this.thread = getThreadFactory().newThread(this);
    }
    
    public void run() {
        runWorker(this);
    }
}

// 核心任务执行循环
private void runWorker(Worker w) {
    Thread wt = Thread.currentThread();
    Runnable task = w.firstTask;
    w.firstTask = null;
    w.unlock(); // 允许中断
    boolean completedAbruptly = true;
    
    try {
        // 不断从队列获取任务并执行
        while (task != null || (task = getTask()) != null) {
            w.lock();
            
            // 检查线程池是否停止
            if ((runStateAtLeast(ctl.get(), STOP) ||
                 (Thread.interrupted() && runStateAtLeast(ctl.get(), STOP)))
                && !wt.isInterrupted())
                wt.interrupt();
            
            try {
                beforeExecute(wt, task);  // 钩子方法
                task.run();
                afterExecute(task, null);
            } catch (Throwable ex) {
                afterExecute(task, ex);
                throw ex;
            } finally {
                task = null;
                w.completedTasks++;
                w.unlock();
            }
        }
        completedAbruptly = false;
    } finally {
        processWorkerExit(w, completedAbruptly);
    }
}

// 关键：getTask() 方法
private Runnable getTask() {
    boolean timedOut = false;
    
    for (;;) {
        int c = ctl.get();
        int rs = runStateOf(c);
        
        // 如果线程池已停止，返回 null
        if (rs >= SHUTDOWN && (rs >= STOP || workQueue.isEmpty())) {
            decrementWorkerCount();
            return null;
        }
        
        int wc = workerCountOf(c);
        
        // 是否需要超时等待
        boolean timed = allowCoreThreadTimeOut || wc > corePoolSize;
        
        if ((wc > maximumPoolSize || (timed && timedOut))
            && (wc > 1 || workQueue.isEmpty())) {
            if (compareAndDecrementWorkerCount(c))
                return null;
            continue;
        }
        
        try {
            // 核心：poll() 超时，take() 永久等待
            Runnable r = timed ?
                workQueue.poll(keepAliveTime, unit) :
                workQueue.take();
            if (r != null)
                return r;
            timedOut = true;
        } catch (InterruptedException retry) {
            timedOut = false;
        }
    }
}
```

**执行流程**：

1. `execute()` → 判断是否创建新线程 → 否则加入队列
2. Worker 不断调用 `getTask()` 从队列获取任务
3. 核心线程永不超时（take）；非核心线程超时退出（poll）
4. 线程复用机制：同一个 Worker 处理多个任务

### 2.3 execute() 提交逻辑

```java
public void execute(Runnable command) {
    if (command == null)
        throw new NullPointerException();
    
    int c = ctl.get();
    
    // 步骤1：工作线程数 < 核心线程数 → 新建线程
    if (workerCountOf(c) < corePoolSize) {
        if (addWorker(command, true))
            return;
        c = ctl.get();
    }
    
    // 步骤2：线程池运行中 → 加入队列
    if (isRunning(c) && workQueue.offer(command)) {
        int recheck = ctl.get();
        // 添加后再次检查线程池状态（防止 SHUTDOWN 期间加入）
        if (!isRunning(recheck) && remove(command))
            reject(command);
        // 如果没有工作线程，创建一个（队列存在但线程已结束）
        else if (workerCountOf(recheck) == 0)
            addWorker(null, false);
    }
    
    // 步骤3：创建非核心线程失败 → 拒绝
    else if (!addWorker(command, false))
        reject(command);
}

// addWorker 源码
private boolean addWorker(Runnable firstTask, boolean core) {
    retry:
    for (int c = ctl.get();;) {
        int rs = runStateOf(c);
        
        // 条件判断（SHUTDOWN/STOP 期间不新建线程）
        if (rs >= SHUTDOWN &&
            !(rs == SHUTDOWN && firstTask == null && !workQueue.isEmpty()))
            return false;
        
        for (;;) {
            int wc = workerCountOf(c);
            int max = core ? corePoolSize : maximumPoolSize;
            
            if (wc >= max)
                return false;
            
            // CAS 增加工作线程计数
            if (compareAndIncrementWorkerCount(c))
                break retry;
            
            c = ctl.get();
            if (runStateOf(c) != rs)
                continue retry;
        }
    }
    
    // 真正创建并启动线程
    boolean workerStarted = false;
    boolean workerAdded = false;
    Worker w = null;
    
    try {
        w = new Worker(firstTask);
        final Thread t = w.thread;
        
        if (t != null) {
            final ReentrantLock mainLock = this.mainLock;
            mainLock.lock();
            try {
                int rs = runStateOf(ctl.get());
                
                if (rs < SHUTDOWN || (rs == SHUTDOWN && firstTask == null)) {
                    if (t.isAlive())
                        throw new IllegalThreadStateException();
                    
                    workers.add(w);
                    int s = workers.size();
                    if (s > largestPoolSize)
                        largestPoolSize = s;
                    workerAdded = true;
                }
            } finally {
                mainLock.unlock();
            }
            
            if (workerAdded) {
                t.start();  // 启动线程
                workerStarted = true;
            }
        }
    } finally {
        if (!workerStarted)
            addWorkerFailed(w);
    }
    
    return workerStarted;
}
```

### 3.2 ScheduledThreadPoolExecutor 源码

```java
public class ScheduledThreadPoolExecutor extends ThreadPoolExecutor {
    
    // 使用优先级队列，按执行时间排序
    private class DelayedWorkQueue extends AbstractQueue<Runnable> {
        private static final int INITIAL_CAPACITY = 16;
        private RunnableScheduledFuture<?>[] queue =
            new RunnableScheduledFuture<?>[INITIAL_CAPACITY];
        private int size = 0;
        private final ReentrantLock lock = new ReentrantLock();
        private final Condition available = lock.newCondition();
        
        // 堆排序：根据 getDelay() 时间排序
        @Override
        public RunnableScheduledFuture<?> poll(long timeout, TimeUnit unit) {
            final ReentrantLock lock = this.lock;
            lock.lockInterruptibly();
            try {
                for (;;) {
                    RunnableScheduledFuture<?> first = queue[0];
                    
                    if (first == null) {
                        // 队列为空，等待 timeout 时间
                        if (!available.awaitNanos(unit.toNanos(timeout)) > 0)
                            return null;
                    } else {
                        long delay = first.getDelay(TimeUnit.NANOSECONDS);
                        if (delay <= 0L)
                            return finishPoll(first);  // 时间到，弹出
                        if (timeout <= 0L)
                            return null;
                        // 等待直到任务就绪
                        timeout = available.awaitNanos(Math.min(delay, timeout));
                    }
                }
            } finally {
                lock.unlock();
            }
        }
    }
    
    public ScheduledFuture<?> schedule(Runnable command, long delay, TimeUnit unit) {
        RunnableScheduledFuture<Void> sft = new ScheduledFutureTask<>(
            command, null, triggerTime(delay, unit), sequencer.getAndIncrement()
        );
        delayedExecute(sft);
        return sft;
    }
    
    // 延迟执行 + 周期执行的关键逻辑
    private void delayedExecute(RunnableScheduledFuture<?> task) {
        if (isShutdown())
            reject(task);
        else {
            super.getQueue().add(task);
            // 如果线程池已关闭，移除任务
            if (isShutdown() && !canRunInCurrentRunState(task.isPeriodic())
                && remove(task))
                task.cancel(false);
            else
                ensurePrestart();  // 确保至少有一个线程启动
        }
    }
}

// ScheduledFutureTask 实现周期执行
private class ScheduledFutureTask<V> extends FutureTask<V>
    implements RunnableScheduledFuture<V> {
    
    private final long sequenceNumber;
    private long time;  // 绝对执行时间
    private final long period;  // 周期（0=一次性，>0=固定速率，<0=固定延迟）
    
    public void run() {
        boolean periodic = isPeriodic();
        
        if (!canRunInCurrentRunState(periodic))
            cancel(false);
        else if (!periodic)
            ScheduledFutureTask.super.run();
        else if (ScheduledFutureTask.super.runAndReset()) {
            // 周期任务：重新设置时间，加回队列
            setNextRunTime();
            reExecutePeriodic(outerTask);
        }
    }
    
    private void setNextRunTime() {
        long p = period;
        if (p > 0)
            time += p;  // 固定速率：time = time + period
        else
            time = triggerTime(-p);  // 固定延迟：当前时间 - period
    }
}
```

## 四、AsyncTask（已弃用，但需理解实现）

### 4.1 源码架构

```java
public abstract class AsyncTask<Params, Progress, Result> {
    
    // 静态线程池
    private static final int CPU_COUNT = Runtime.getRuntime().availableProcessors();
    private static final int CORE_POOL_SIZE = Math.max(2, Math.min(CPU_COUNT - 1, 4));
    private static final int MAXIMUM_POOL_SIZE = CPU_COUNT * 2 + 1;
    private static final int KEEP_ALIVE_TIME_SECONDS = 30;
    
    private static final ThreadFactory sThreadFactory = new ThreadFactory() {
        private final AtomicInteger mCount = new AtomicInteger(1);
        
        public Thread newThread(Runnable r) {
            return new Thread(r, "AsyncTask #" + mCount.getAndIncrement());
        }
    };
    
    // 关键：SerialExecutor 序列化执行（默认）
    private static class SerialExecutor implements Executor {
        final ArrayDeque<Runnable> mTasks = new ArrayDeque<>();
        Runnable mActive;
        
        public synchronized void execute(final Runnable r) {
            mTasks.offer(new Runnable() {
                public void run() {
                    try {
                        r.run();
                    } finally {
                        scheduleNext();
                    }
                }
            });
            
            if (mActive == null) {
                scheduleNext();
            }
        }
        
        protected synchronized void scheduleNext() {
            if ((mActive = mTasks.poll()) != null) {
                THREAD_POOL_EXECUTOR.execute(mActive);  // 一次只执行一个
            }
        }
    }
    
    public static final Executor SERIAL_EXECUTOR = new SerialExecutor();
    public static final Executor THREAD_POOL_EXECUTOR = 
        new ThreadPoolExecutor(
            CORE_POOL_SIZE,
            MAXIMUM_POOL_SIZE,
            KEEP_ALIVE_TIME_SECONDS,
            TimeUnit.SECONDS,
            new LinkedBlockingQueue<>(128),  // 队列容量限制
            sThreadFactory
        );
    
    // 执行流程
    @MainThread
    public final AsyncTask<Params, Progress, Result> execute(Params... params) {
        // 内部使用 SerialExecutor（确保串行）
        return executeOnExecutor(SERIAL_EXECUTOR, params);
    }
    
    public final AsyncTask<Params, Progress, Result> executeOnExecutor(
        Executor exec, Params... params) {
        
        mWorker = new WorkerRunnable<Params, Result>() {
            public Result call() throws Exception {
                // 子线程执行
                return doInBackground(mParams);
            }
        };
        
        mFuture = new FutureTask<>(mWorker) {
            @Override
            protected void done() {
                try {
                    postResultIfNotInvoked(get());
                } catch (Exception e) {
                    // 发送异常到主线程
                    postResultIfNotInvoked(null);
                }
            }
        };
        
        // 提交给 Executor（SerialExecutor 或自定义）
        exec.execute(mFuture);
        
        return this;
    }
    
    // 结果回调到主线程
    private void postResultIfNotInvoked(Result result) {
        @SuppressWarnings("unchecked")
        final Message message = Message.obtain();
        message.what = MESSAGE_POST_RESULT;
        message.obj = new AsyncTaskResult<>(this, result);
        sHandler.sendMessage(message);  // 发送到主线程 Handler
    }
}
```

**AsyncTask 设计缺陷**：

1. 默认串行执行 - 多个异步任务会排队
2. 队列深度固定（128）- 超出则抛异常
3. 屏幕旋转导致内存泄漏
4. **已在 API 30 弃用**，改用 Coroutines

## 五、Android 特有线程模型

### 5.1 HandlerThread

```java
public class HandlerThread extends Thread {
    
    private int mPriority;
    private int mTid = -1;
    private Looper mLooper;
    private final Object mLooperSemaphore = new Object();
    
    public HandlerThread(String name) {
        super(name);
        mPriority = Process.THREAD_PRIORITY_DEFAULT;
    }
    
    @Override
    public void run() {
        mTid = Process.myTid();
        Looper.prepare();  // 创建 Looper 和 MessageQueue
        synchronized (mLooperSemaphore) {
            mLooper = Looper.myLooper();  // 获取当前线程 Looper
            mLooperSemaphore.notifyAll();  // 唤醒等待的 getLooper()
        }
        
        Process.setThreadPriority(mPriority);
        onLooperPrepared();  // 钩子方法
        
        Looper.loop();  // 阻塞循环处理消息
    }
    
    // 阻塞获取 Looper
    public Looper getLooper() {
        if (!isAlive()) return null;
        
        synchronized (mLooperSemaphore) {
            while (isAlive() && mLooper == null) {
                try {
                    mLooperSemaphore.wait();
                } catch (InterruptedException e) {
                }
            }
        }
        return mLooper;
    }
    
    public boolean quit() {
        Looper looper = getLooper();
        if (looper != null) {
            looper.quit();
            return true;
        }
        return false;
    }
}

// 使用示例
HandlerThread thread = new HandlerThread("MyThread");
thread.start();
Handler handler = new Handler(thread.getLooper());
handler.post(() -> {
    // 在 thread 中执行
});
thread.quit();
```

**vs ThreadPoolExecutor**：

- HandlerThread：单线程 + 消息队列（顺序处理）
- ThreadPoolExecutor：多线程 + 任务队列（并发处理）

## 七、Kotlin Coroutines 调度器

### 7.1 Dispatcher 实现对比

```kotlin
// 核心调度器
Dispatchers.Main        // 主线程（UI 更新）
Dispatchers.IO          // 单独线程池（网络、文件I/O）
Dispatchers.Default     // CPU 密集型，共享线程池
Dispatchers.Unconfined  // 不切换线程（危险）

// IO Dispatcher 源码
public object Dispatchers {
    @JvmStatic
    public val IO: CoroutineDispatcher = IO
}

// ExecutorCoroutineDispatcher
internal class ExecutorCoroutineDispatcher(
    private val executor: Executor,
    private val removesFutureOnCancellation: Boolean = false
) : CoroutineDispatcher() {
    
    override fun dispatch(context: CoroutineContext, block: Runnable) {
        executor.execute(block)  // 委托给 Executor
    }
}

// Dispatchers.IO 实际使用 LimitedDispatcher
internal class LimitedDispatcher(
    private val dispatcher: ExecutorCoroutineDispatcher,
    private val parallelism: Int  // 最大并发数
) : CoroutineDispatcher() {
    
    private val runningWorkers = AtomicInteger(0)
    private val queue = ArrayDeque<Runnable>()
    private val lock = ReentrantLock()
    private val notFull = lock.newCondition()
    
    override fun dispatch(context: CoroutineContext, block: Runnable) {
        lock.withLock {
            if (runningWorkers >= parallelism) {
                // 超过并发限制，加入队列
                queue.add(block)
            } else {
                runningWorkers.incrementAndGet()
                dispatcher.execute {
                    try {
                        block.run()
                    } finally {
                        // 处理队列中的下一个任务
                        var next: Runnable? = null
                        lock.withLock {
                            if (queue.isNotEmpty()) {
                                next = queue.removeFirst()
                            } else {
                                runningWorkers.decrementAndGet()
                                notFull.signalAll()
                            }
                        }
                        
                        next?.let { 
                            dispatch(context, it) 
                        }
                    }
                }
            }
        }
    }
}

// 使用示例
launch(Dispatchers.IO) {
    val data = fetchFromNetwork()  // 在 IO 线程执行
    withContext(Dispatchers.Main) {
        updateUI(data)  // 切回主线程
    }
}
```

**核心机制**：

- Dispatcher 是 Coroutine 的线程调度器
- IO Dispatcher 使用 LimitedDispatcher 限制并发数（默认 64）
- Default Dispatcher 共享 CPU 核心数线程

```java
        });
```

### 8.2 Glide 图片加载线程池

```java
public class GlideExecutor extends ThreadPoolExecutor {
    
    private static final int CORE_POOL_SIZE =
        Math.max(2, Math.min(
            Runtime.getRuntime().availableProcessors() - 1, 4));
    
    private GlideExecutor(
        int corePoolSize, int maximumPoolSize,
        long keepAliveTime, TimeUnit unit,
        BlockingQueue<Runnable> workQueue,
        ThreadFactory threadFactory,
        RejectedExecutionHandler handler) {
        super(corePoolSize, maximumPoolSize, keepAliveTime, unit,
              workQueue, threadFactory, handler);
    }
    
    public static GlideExecutor newSourceExecutor() {
        // 磁盘缓存读取（IO 密集）
        return new GlideExecutor(
            CORE_POOL_SIZE, CORE_POOL_SIZE * 2,
            0L, TimeUnit.MILLISECONDS,
            new PriorityBlockingQueue<>(),  // 优先级队列
            new DefaultThreadFactory("disk-cache"),
            new DiscardPolicy()  // 队列满时丢弃
        );
    }
    
    public static GlideExecutor newAnimationExecutor() {
        // 动画处理（单线程）
        return new GlideExecutor(
            1, 1,
            0L, TimeUnit.MILLISECONDS,
            new LinkedBlockingQueue<>(),
            new DefaultThreadFactory("animation"),
            new DiscardPolicy()
        );
    }
}
```

```kotlin
// CachedWorkerPool 源码简化
class CachedWorkerPool(
    val keepAliveTime: Long,
    val timeUnit: TimeUnit
) {
    private val workerCache = ConcurrentHashMap<Long, Future<WorkerThread>>()
    
    fun getWorker(): WorkerThread {
        // 检查缓存中是否有空闲线程
        val existing = workerCache.entries
            .find { !it.value.get().busy }
        
        return if (existing != null) {
            existing.value.get()  // 复用空闲线程
        } else {
            val worker = WorkerThread(this)
            val future = FutureTask { worker }
            workerCache.put(System.currentTimeMillis(), future)
            future.get()
        }
    }
}
```

### 10.2 监控与调试

```java
public class MonitoredThreadPoolExecutor extends ThreadPoolExecutor {
    
    private final String name;
    private final AtomicLong totalTaskCount = new AtomicLong(0);
    private final AtomicLong totalCompletedCount = new AtomicLong(0);
    private final AtomicLong totalRejectCount = new AtomicLong(0);
    
    @Override
    protected void beforeExecute(Thread t, Runnable r) {
        totalTaskCount.incrementAndGet();
        Log.d(TAG, String.format(
            "[%s] Task start. Active: %d, Queue: %d",
            name, getActiveCount(), getQueue().size()
        ));
    }
    
    @Override
    protected void afterExecute(Runnable r, Throwable ex) {
        totalCompletedCount.incrementAndGet();
        if (ex != null) {
            Log.e(TAG, "[%s] Task failed", name, ex);
        }
    }
    
    @Override
    public void rejectedExecution(Runnable r, ThreadPoolExecutor executor) {
        totalRejectCount.incrementAndGet();
        Log.w(TAG, String.format(
            "[%s] Task rejected. Reason: %s",
            name, getRejectedExecutionHandler()
        ));
    }
    
    public void printStats() {
        Log.i(TAG, String.format(
            "[%s] Total: %d, Completed: %d, Rejected: %d, " +
            "Queue: %d, Active: %d, CorePool: %d",
            name, 
            totalTaskCount.get(),
            totalCompletedCount.get(),
            totalRejectCount.get(),
            getQueue().size(),
            getActiveCount(),
            getCorePoolSize()
        ));
    }
}

// 使用

    4, 8, 60, TimeUnit.SECONDS,

scheduler.scheduleAtFixedRate(
```

## 十一、高频面试题对照

### Q1：ThreadPoolExecutor 提交任务流程？

**关键代码路径**：

```
execute() 
  → workerCountOf < corePoolSize? addWorker(true)
  → 否则 workQueue.offer()
  → 否则 addWorker(false, maxPoolSize)
  → 否则 reject()
```

### Q2：为什么 AsyncTask 默认串行？

**答**：使用 SerialExecutor 包装，每次只从 THREAD_POOL_EXECUTOR 执行一个任务，其余在 ArrayDeque 排队。

### Q3：Glide 为什么用 PriorityBlockingQueue？

**答**：优先级队列按图片尺寸、优先级排序，确保屏幕可见图片先加载。

### Q4：OkHttp 为什么 maxRequests=64 且 maxRequestsPerHost=5？

**答**：防止单 Host 过载；全局 64 限流整体带宽。

### Q5：Coroutines IO Dispatcher 为什么默认限流 64？

**答**：避免连接池溢出，与 OkHttp maxRequests 对标。

### Q6：shutdown vs shutdownNow 区别？

```java
shutdown()      // 不接收新任务，等待队列任务完成
shutdownNow()   // 立即中断所有任务，返回未执行列表
```

**关键记忆点**：

1. **ThreadPoolExecutor 是基础** - 其他都是包装或优化
2. **CAS 原子操作** - ctl 同时保存状态 + 线程数，无竞态
3. **队列选择很关键** - LinkedBlockingQueue (有界)、SynchronousQueue (无缓冲)、PriorityBlockingQueue (优先级)
4. **限流策略不同** - 固定容量限流（传统）vs 并发数限流（Coroutines）
5. **MainThread 安全** - Handler 必须用于主线程回调
