
## 什么是 Dagger2

- [[33 Hilt  Dagger  依赖注入.md]]  Hilt依赖注入

Dagger2 是 **Google 开发的编译期依赖注入 (DI) 框架**，是 Android 开发中最流行的 DI 工具。它通过注解处理器在编译时生成依赖注入代码，而不是运行时反射，因此性能极高。

---

## 什么时候用到

### 1. **项目规模较大**

- 多层级架构（UI层、业务层、数据层）
- 组件间耦合度高

### 2. **依赖关系复杂**

- 深层次的对象构建
- 单例、工厂、作用域管理

### 3. **需要测试**

- Mock对象注入
- 单元测试、集成测试

### 4. **MVVM/Clean Architecture**

- 配合 ViewModel、Repository、DataSource 使用

---

## 作用

|作用|说明|
|---|---|
|**解耦**|对象创建与使用分离，降低类间依赖|
|**自动化**|自动生成工厂代码，减少手动 new|
|**生命周期管理**|通过Scope控制对象生命周期（单例、工厂等）|
|**可维护性**|集中管理依赖关系，易于后期修改|
|**可测试性**|易于注入Mock/Stub对象进行测试|

## 核心概念

### 1. **@Inject** - 标记依赖

```kotlin
class UserRepository @Inject constructor(
    private val apiService: ApiService
) {
    // 依赖会由Dagger2自动注入
}

class UserViewModel @Inject constructor(
    private val repository: UserRepository
) {
    // ...
}
```

### 2. **@Module** - 定义如何提供依赖

```kotlin
@Module
class AppModule {
    @Provides
    @Singleton
    fun provideApiService(): ApiService {
        return Retrofit.Builder()
            .baseUrl("https://api.example.com")
            .build()
            .create(ApiService::class.java)
    }
    
    @Provides
    @Singleton
    fun provideDatabase(@ApplicationContext context: Context): AppDatabase {
        return Room.databaseBuilder(context, AppDatabase::class.java, "app.db")
            .build()
    }
}
```

### 3. **@Component** - 组装模块

```kotlin
@Singleton
@Component(modules = [AppModule::class, RepositoryModule::class])
interface AppComponent {
    // 用于注入到Activity/Fragment
    fun inject(activity: MainActivity)
    fun inject(fragment: HomeFragment)
    
    // 或者直接获取对象
    fun getUserRepository(): UserRepository
}
```

### 4. **@Scope** - 控制生命周期

```kotlin
// 自定义作用域
@Scope
@Retention(AnnotationRetention.RUNTIME)
annotation class ActivityScope

@ActivityScope
@Component
interface ActivityComponent {
    fun inject(activity: DetailActivity)
}
```

## 完整使用示例

### **步骤1: 添加依赖**

```gradle
dependencies {
    implementation "com.google.dagger:dagger:2.48"
    kapt "com.google.dagger:dagger-compiler:2.48"
    
    // 如果使用Android特性
    implementation "com.google.dagger:dagger-android:2.48"
    kapt "com.google.dagger:dagger-android-processor:2.48"
}
```

### **步骤2: 定义Module**

```kotlin
// 数据层模块
@Module
class DataModule {
    @Provides
    @Singleton
    fun provideApiService(): ApiService {
        return OkHttpClient.Builder()
            .addInterceptor(loggingInterceptor)
            .build()
            .let {
                Retrofit.Builder()
                    .client(it)
                    .baseUrl(API_BASE_URL)
                    .addConverterFactory(GsonConverterFactory.create())
                    .build()
                    .create(ApiService::class.java)
            }
    }
    
    @Provides
    @Singleton
    fun provideUserRepository(apiService: ApiService): UserRepository {
        return UserRepository(apiService)
    }
}

// 业务层模块
@Module
class ViewModelModule {
    @Provides
    fun provideUserViewModel(repository: UserRepository): UserViewModel {
        return UserViewModel(repository)
    }
}
```

### **步骤3: 创建Component**

```kotlin
@Singleton
@Component(modules = [DataModule::class, ViewModelModule::class])
interface AppComponent {
    fun inject(mainActivity: MainActivity)
    fun getUserRepository(): UserRepository
}
```

### **步骤4: 在Application中初始化**

```kotlin
class MyApp : Application() {
    companion object {
        lateinit var appComponent: AppComponent
    }
    
    override fun onCreate() {
        super.onCreate()
        appComponent = DaggerAppComponent.create()  // Dagger2生成的类
    }
}
```

### **步骤5: 在Activity中使用**

```kotlin
class MainActivity : AppCompatActivity() {
    @Inject
    lateinit var userRepository: UserRepository
    
    @Inject
    lateinit var userViewModel: UserViewModel
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 进行注入
        MyApp.appComponent.inject(this)
        
        // 现在可以直接使用
        userRepository.getUsers()
    }
}
```

## Dagger2 解决的问题

### 1. **手动创建对象的繁琐**

❌ 没有DI:

```kotlin
val apiService = ApiService()
val database = AppDatabase.getInstance(context)
val userRepository = UserRepository(apiService, database)
val userViewModel = UserViewModel(userRepository)
```

✅ 使用Dagger2: 直接 `@Inject` 自动注入

### 2. **单例管理混乱**

```kotlin
// 传统方式容易写错
object ServiceLocator {
    private var apiService: ApiService? = null
    
    fun getApiService(): ApiService {
        if (apiService == null) {
            apiService = ApiService()  // 线程不安全
        }
        return apiService
    }
}

// Dagger2 @Singleton保证线程安全
@Provides
@Singleton
fun provideApiService(): ApiService = ApiService()
```

### 3. **依赖层级深导致的问题**

```kotlin
// 5层依赖关系，手动管理很容易出错
val a = A()
val b = B(a)
val c = C(b)
val d = D(c)
val e = E(d)  // 如果中间任何一层改变，都需要修改

// Dagger2自动处理，改变中间层时其他层自动适应
```

### 4. **测试困难**

```kotlin
// Dagger2使得Mock注入变得简单
@Module
class TestDataModule {
    @Provides
    @Singleton
    fun provideApiService(): ApiService = MockApiService()
}

// 编译单元测试专用的Component
@Singleton
@Component(modules = [TestDataModule::class])
interface TestAppComponent
```

## Dagger2 vs 其他方案

|方案|优点|缺点|
|---|---|---|
|**Dagger2**|编译期生成，性能好，类型安全|学习曲线陡，编译时间长|
|**Hilt**|Dagger2上层封装，简化使用|需要Android特定知识|
|**Koin**|轻量，运行时反射，学习简单|性能不如Dagger2|
|**Spring**|功能强大|不适合Android|

## 最佳实践

```kotlin
// 1. 一个App一个全局AppComponent
// 2. 为不同Feature创建子Component
// 3. 用@Singleton标记全局单例
// 4. 用自定义@Scope标记局部生命周期
// 5. Module职责单一（DataModule、ViewModelModule等分离）
// 6. 优先@Inject构造函数注入，其次@Provides方法注入
```

**总结**: Dagger2 是解决大型Android项目依赖管理的利器，虽然初期学习成本高，但对代码质量、可维护性和可测试性提升巨大。💡
