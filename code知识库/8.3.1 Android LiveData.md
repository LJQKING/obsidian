
### 一、LiveData是什么

- [[24.3  LiveData｜RxJava｜Flow 不同场景实现.md]]  LiveData
- [[8.3 LiveData缺点.md]]  LiveData
**LiveData 是 Android Jetpack 架构组件中的一个可观察的数据存储器类**。与传统的观察者模式不同，**LiveData 最重要的特点是具有“生命周期感知”能力**。

这意味着它能够感知并遵循其他应用组件（如 Activity、Fragment 或 Service）的生命周期状态。它的核心行为准则由官方的 `Lifecycle` 库定义：**LiveData 只会将数据更新通知给处于活跃生命周期状态（即 `STARTED` 或 `RESUMED` 状态）的观察者**。

> **核心特性与优势**：
> - **生命周期感知**：自动管理订阅，避免内存泄漏。当观察者（如 Activity）的生命周期结束时，LiveData 会自动清除对它的引用。
> - **避免崩溃**：不会向已停止的 Activity 发送更新，避免因更新已销毁的 UI 而导致的崩溃。
> - **数据始终最新**：非活跃的观察者在重新变为活跃状态时，会立即收到最新的数据。
> - **无需手动处理生命周期**：UI 组件只需观察数据，所有生命周期管理都由 LiveData 自动完成。

### 二、核心使用方式及区别

在实际开发中，主要涉及到 `LiveData` 和 `MutableLiveData` 两个类，它们在设计和使用上有明确的职责划分。

#### 1. `LiveData` vs `MutableLiveData`：“只读”与“读写”的区别

这是最核心的区别。可以用一句话概括：**`LiveData` 是“只读”的，而 `MutableLiveData` 是“可读可写”的**。

| 特性 | `LiveData` | `MutableLiveData` |
| :--- | :--- | :--- |
| **本质** | 抽象基类 | `LiveData` 的子类 |
| **数据操作** | **不可变**。没有公开修改数据的方法，外部只能“观察（`observe`）”数据 | **可变**。公开了 `setValue()` 和 `postValue()` 方法，允许修改数据 |
| **使用场景** | **暴露给 UI 层（Activity/Fragment）**。UI 只需读取和监听数据，不应有修改权限 | **在 ViewModel 内部使用**。ViewModel 负责业务逻辑，需要有能力更新数据 |
| **实例化** | 抽象类，不能直接 `new` | 普通类，可以直接 `new` |

> **MVVM 架构中的黄金法则**：在 ViewModel 内部使用 `MutableLiveData` 来存储和修改数据，但对外暴露时，**必须将其类型声明为不可变的 `LiveData`**。这能确保 UI 层只有数据的“读”权限，防止 UI 意外修改数据，保持了数据流向的单向性和清晰性。

```kotlin
// 标准的 ViewModel 写法
class MyViewModel : ViewModel() {
    // 1. 私有的、可变的 MutableLiveData，只在 ViewModel 内部修改
    private val _userName = MutableLiveData<String>()

    // 2. 对外暴露不可变的 LiveData，UI 只能 observe，不能 set
    val userName: LiveData<String> = _userName

    // 3. ViewModel 通过修改私有的 _userName 来更新数据
    fun fetchUser() {
        // 模拟网络请求...
        _userName.value = "Alice" // 在主线程更新
        // 或在子线程: _userName.postValue("Alice")
    }
}
```

#### 2. `setValue()` vs `postValue()`：线程安全的区别

这两个方法用于更新 `MutableLiveData` 中的数据，主要区别在于线程安全性。

| 方法 | 线程要求 | 行为 |
| :--- | :--- | :--- |
| **`setValue(T value)`** | **必须在主线程（UI 线程）调用** | 立即更新数据并通知所有活跃观察者。 |
| **`postValue(T value)`** | **可在任何线程（包括后台线程）调用** | 内部会将更新任务 `post` 到主线程的 `Handler` 中，然后在主线程执行 `setValue()`，安全地更新 UI。 |

**最佳实践**：
- 在 ViewModel 中，如果数据更新操作本身就在主线程（如响应用户点击），可直接使用 `setValue()`。
- 在子线程（如网络请求回调、数据库查询）中更新数据时，**必须使用 `postValue()`**，以避免因跨线程更新 UI 而引发崩溃。

#### 3. `observe()` vs `observeForever()`：生命周期绑定的区别

这是观察 LiveData 的两种方式，它们与生命周期的绑定程度不同。

| 方法 | 生命周期绑定 | 自动清理 | 使用场景 |
| :--- | :--- | :--- | :--- |
| **`observe(LifecycleOwner, Observer)`** | **绑定**。需要传入 `LifecycleOwner`（如 Activity/Fragment） | **是**。当 `LifecycleOwner` 销毁时，观察者会自动被移除 | **绝大多数情况**。在 Activity 或 Fragment 中观察数据，安全无忧。 |
| **`observeForever(Observer)`** | **不绑定**。观察者会一直处于活跃状态 | **否**。必须手动调用 `removeObserver()` 移除，否则会导致内存泄漏 | **特殊场景**。如需要在服务或非生命周期组件中监听数据，且能保证手动清理。 |

**重要提示**：`observe()` 方法要求**在主线程调用**。

### 三、具体场景代码实现

#### 场景一：MVVM 架构中，ViewModel 配合 LiveData 更新 UI

这是 LiveData 最经典、最标准的用法。

**1. 创建 ViewModel，持有 LiveData**

```kotlin
class UserViewModel : ViewModel() {
    // 私有的 MutableLiveData
    private val _userName = MutableLiveData<String>()
    // 对外暴露不可变的 LiveData
    val userName: LiveData<String> = _userName

    private val _isLoading = MutableLiveData<Boolean>()
    val isLoading: LiveData<Boolean> = _isLoading

    fun loadUser() {
        _isLoading.value = true
        // 模拟网络请求 (使用协程)
        viewModelScope.launch {
            delay(2000) // 模拟耗时操作
            _userName.postValue("John Doe") // 在子线程使用 postValue
            _isLoading.postValue(false)
        }
    }
}
```

**2. Activity/Fragment 中观察数据**

```kotlin
class MainActivity : AppCompatActivity() {
    private lateinit var viewModel: UserViewModel

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        viewModel = ViewModelProvider(this).get(UserViewModel::class.java)

        // 观察用户名变化
        viewModel.userName.observe(this, Observer { name ->
            // 此回调只在 Activity 处于 STARTED 或 RESUMED 时才会触发
            textViewUserName.text = name
        })

        // 观察加载状态
        viewModel.isLoading.observe(this, Observer { isLoading ->
            progressBar.visibility = if (isLoading) View.VISIBLE else View.GONE
        })

        // 触发数据加载
        buttonLoad.setOnClickListener {
            viewModel.loadUser()
        }
    }
}
```

#### 场景二：在数据绑定（DataBinding）中使用 LiveData

LiveData 可以与 DataBinding 库无缝集成，实现 UI 的自动更新。

**1. 在布局文件中绑定 LiveData 对象**

```xml
<layout>
    <data>
        <variable
            name="viewModel"
            type="com.example.MyViewModel" />
    </data>
    <LinearLayout>
        <TextView
            android:text="@{viewModel.userName}" />
    </LinearLayout>
</layout>
```

**2. 在 Activity 中设置生命周期所有者**

```kotlin
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        val binding: ActivityMainBinding = DataBindingUtil.setContentView(this, R.layout.activity_main)
        binding.lifecycleOwner = this // 关键！让绑定感知生命周期
        binding.viewModel = ViewModelProvider(this).get(MyViewModel::class.java)
    }
}
```

当 `ViewModel` 中的 `userName` 发生变化时，`TextView` 会自动更新，无需手动调用 `observe`。

### 四、实现原理

LiveData 的实现是建立在 **观察者模式** 和 **Lifecycle 生命周期库** 之上的。

#### 1. 核心工作流程

**① 注册观察者 (`observe()`)**
当调用 `liveData.observe(this, observer)` 时，LiveData 内部会进行以下操作：
- **检查生命周期**：如果传入的 `LifecycleOwner` 已经处于 `DESTROYED` 状态，则直接忽略，不进行观察。
- **包装观察者**：将传入的 `Observer` 和 `LifecycleOwner` 包装成一个 `LifecycleBoundObserver` 对象。这个包装类实现了 `LifecycleEventObserver` 接口，能感知生命周期变化。
- **关联生命周期**：将 `LifecycleBoundObserver` 添加到 `LifecycleOwner` 的生命周期观察者列表中。这样，当 Activity/Fragment 的生命周期状态发生变化时，LiveData 就能收到通知。

**② 数据更新 (`setValue()/postValue()`)**
- 调用 `setValue()` 会直接更新内部存储的数据 `mData`，并触发一个 `dispatchingValue()` 方法，开始通知所有观察者。
- `postValue()` 则是通过主线程的 `Handler` 发送一个任务，在任务中调用 `setValue()`，确保更新操作在主线程执行。

**③ 通知观察者 (`onChanged()`)**
- 当 LiveData 准备通知观察者时，会检查每个 `LifecycleBoundObserver` 对应的 `LifecycleOwner` 的当前状态。
- **只有状态为 `STARTED` 或 `RESUMED` 的观察者才会收到通知**。
- 如果观察者处于非活跃状态（如后台的 Activity），则不会收到此次更新。但当它重新变为活跃状态时，LiveData 会**立即用最新数据**再次通知它。

**④ 自动清理**
当 `LifecycleOwner`（如 Activity）的生命周期状态变为 `DESTROYED` 时，`LifecycleBoundObserver` 会收到 `ON_DESTROY` 事件。此时，LiveData 会自动调用 `removeObserver()`，移除对该观察者的引用。这一机制从根本上杜绝了因 Activity 未及时取消注册而引发的**内存泄漏**问题。

#### 2. 关键源码类

- **`LiveData`**：核心类，管理观察者列表和数据，控制通知逻辑。
- **`Observer`**：观察者接口，定义 `onChanged()` 回调方法。
- **`ObserverWrapper`**：观察者的包装抽象类，记录观察者的版本号（`mLastVersion`）并判断其是否活跃。
- **`LifecycleBoundObserver`**：继承 `ObserverWrapper` 并实现 `LifecycleEventObserver`，是连接 LiveData 和 Lifecycle 的关键桥梁，负责感知生命周期并据此控制通知。
- **`AlwaysActiveObserver`**：另一种观察者包装类，它不感知生命周期，会始终认为自己是活跃的，对应 `observeForever()` 方法。

---

### 五、总结

- **LiveData 是什么**：一个**生命周期感知型**的可观察数据存储器，是 Android 官方推荐的用于构建响应式 UI 的组件。
- **核心区别**：`LiveData`（只读）与 `MutableLiveData`（读写）的设计区分了数据层和 UI 层的职责；`setValue()`（主线程）与 `postValue()`（任意线程）保证了线程安全；`observe()`（自动清理）与 `observeForever()`（手动清理）提供了灵活的生命周期管理选项。
- **实现原理**：核心是**观察者模式**加上 **Lifecycle 生命周期库**。LiveData 通过包装观察者并绑定到 `LifecycleOwner`，实现了只在活跃状态通知更新，并在宿主销毁时自动清理，从而保证了数据驱动 UI 的安全和高效。
