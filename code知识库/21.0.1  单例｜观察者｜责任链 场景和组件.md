
## 1. 单例模式（Singleton Pattern）

### 核心原理

- [[21 单例模式（Singleton Pattern）.md]]  设计模式
- [[21.0  单例｜工厂｜观察者｜责任链｜建造者模式.md]]  设计模式
**确保一个类只有一个实例，并提供全局访问点。**

### Android 常见应用

#### 1.1 Application（进程级单例）

```kotlin
// Application是进程生命周期内的单例
class MyApp : Application() {
    companion object {
        private lateinit var instance: MyApp
        
        fun getInstance(): MyApp = instance
    }
    
    override fun onCreate() {
        super.onCreate()
        instance = this
    }
}
```

**原理**：

- System.loadLibrary 加载 app 时创建唯一 Application 实例
- 声明周期：进程启动 → onCreate() → 进程销毁
- 系统保证全局唯一性（不需要手动同步）

#### 1.2 SharedPreferences 单例

```kotlin
// 错误方式：每次 getSharedPreferences 都创建新实例
val sp1 = context.getSharedPreferences("config", Context.MODE_PRIVATE)
val sp2 = context.getSharedPreferences("config", Context.MODE_PRIVATE)
// sp1 !== sp2 (内存中不同对象)

// 正确方式：系统级单例缓存
class PreferencesManager private constructor(context: Context) {
    private val sp = context.getSharedPreferences("config", Context.MODE_PRIVATE)
    
    companion object {
        @Volatile private var instance: PreferencesManager? = null
        
        fun getInstance(context: Context): PreferencesManager =
            instance ?: synchronized(this) {
                instance ?: PreferencesManager(context).also { instance = it }
            }
    }
    
    fun getString(key: String): String = sp.getString(key, "")
}
```

**原理**：

- ContextImpl 内部维护 `Map<String, SharedPreferences>` 缓存
- 同名 name 返回同一对象引用
- 双重检查锁定（Double-Checked Locking）保证线程安全

#### 1.3 Handler（Looper 单例）

```kotlin
// Handler 依赖 Looper 单例
class Handler(looper: Looper = Looper.myLooper()!!) {
    // ...
}

// Looper.myLooper() 原理
object Looper {
    private val sThreadLocal = ThreadLocal<Looper>()
    
    fun myLooper(): Looper? = sThreadLocal.get()
    
    fun prepare() {
        if (sThreadLocal.get() != null) {
            throw RuntimeException("Only one Looper may be created per thread")
        }
        sThreadLocal.set(Looper())
    }
}
```

**原理**：

- 使用 ThreadLocal 实现**线程级单例**
- 每个线程最多一个 Looper
- 避免了全局同步的开销

#### 1.4 RxJava Schedulers 单例

```kotlin
// Schedulers.io() 返回全局共享的线程池单例
Schedulers.io()  // 多次调用返回同一实例
    .scheduleDirect { /* ... */ }
```

### 单例模式的三种实现

|实现方式|优点|缺点|使用场景|
|---|---|---|---|
|**饿汉式**|线程安全，加载快|浪费内存|SharedPreferences|
|**懒汉式 (DCL)**|延迟加载|代码复杂|大对象|
|**静态内部类**|线程安全+延迟加载|反射破坏|首选|
|**ThreadLocal**|线程隔离|内存泄漏风险|Handler/Looper|

```kotlin
// 最佳实践：静态内部类 + 伴生对象
class DatabaseManager private constructor() {
    companion object {
        val instance: DatabaseManager by lazy(LazyThreadSafetyMode.SYNCHRONIZED) {
            DatabaseManager()
        }
    }
}

// 或使用对象表达式
object DatabaseManager {
    // Kotlin 编译器保证单例
}
```

## 2. 观察者模式（Observer Pattern）

### 核心原理

**定义一种一对多的依赖关系，当主体状态改变时，通知所有依赖者。**

### Android 常见应用

#### 2.1 LiveData（推荐）

```kotlin
// LiveData = 可观察的生命周期感知数据容器

class UserViewModel : ViewModel() {
    private val _userLiveData = MutableLiveData<User>()
    val userLiveData: LiveData<User> = _userLiveData
    
    fun loadUser(id: String) {
        viewModelScope.launch {
            val user = repository.getUser(id)
            _userLiveData.postValue(user)  // 通知所有观察者
        }
    }
}

// Activity 中订阅
class UserActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        viewModel.userLiveData.observe(this) { user ->
            // 生命周期感知：销毁时自动取消订阅
            updateUI(user)
        }
    }
}
```

**原理分析**：

```kotlin
// LiveData 简化原理
open class LiveData<T> {
    private val observers = mutableMapOf<Observer<T>, LifecycleBoundObserver>()
    
    // 发布数据
    protected fun postValue(value: T) {
        // 在主线程分发给所有活跃观察者
        observers.forEach { (_, boundObserver) ->
            if (boundObserver.isActive) {
                boundObserver.observer.onChanged(value)
            }
        }
    }
    
    // 订阅
    fun observe(owner: LifecycleOwner, observer: Observer<T>) {
        val boundObserver = LifecycleBoundObserver(owner, observer)
        owner.lifecycle.addObserver(boundObserver)  // 生命周期感知
        observers[observer] = boundObserver
    }
}
```

**优势**：

- ✅ 自动取消订阅（生命周期感知）
- ✅ 防止内存泄漏
- ✅ 粘性事件（新订阅者收到最后一次值）

#### 2.2 BroadcastReceiver（进程间通信）

```kotlin
// 观察者：BroadcastReceiver
class BatteryReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context?, intent: Intent?) {
        val level = intent?.getIntExtra(BatteryManager.EXTRA_LEVEL, -1) ?: return
        Toast.makeText(context, "Battery: $level%", Toast.LENGTH_SHORT).show()
    }
}

// 发布者：注册观察者
class MainActivity : AppCompatActivity() {
    private val batteryReceiver = BatteryReceiver()
    
    override fun onStart() {
        super.onStart()
        val filter = IntentFilter(Intent.ACTION_BATTERY_CHANGED)
        registerReceiver(batteryReceiver, filter)  // 订阅
    }
    
    override fun onStop() {
        super.onStop()
        unregisterReceiver(batteryReceiver)  // 取消订阅
    }
}
```

**原理**：

```
ActivityManagerService (发布者)
    ↓
BroadcastQueue.broadcastIntent()
    ↓ (查询所有订阅的 Receiver)
PackageManagerService.queryBroadcastReceivers()
    ↓
遍历分发给每个 BroadcastReceiver
    ↓
ReceiverDispatcher.performReceive()
```

#### 2.3 StateFlow / SharedFlow（协程观察者）

```kotlin
// StateFlow = 可感知状态的观察者流
class SearchViewModel : ViewModel() {
    private val _searchResults = MutableStateFlow<List<Item>>(emptyList())
    val searchResults: StateFlow<List<Item>> = _searchResults.asStateFlow()
    
    fun search(query: String) {
        viewModelScope.launch {
            val results = repository.search(query)
            _searchResults.emit(results)  // 通知所有订阅者
        }
    }
}

// Fragment 中使用
class SearchFragment : Fragment() {
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        viewLifecycleOwner.lifecycleScope.launch {
            // 只在 STARTED 状态收集
            viewModel.searchResults.collect { results ->
                adapter.submitList(results)
            }
        }
    }
}
```

**vs LiveData**：

|特性|LiveData|StateFlow|
|---|---|---|
|粘性事件|✅|✅|
|协程支持|⚠️ (Flow转换)|✅|
|背压处理|❌|✅|
|非主线程post|❌ (需postValue)|✅ (emit)|

#### 2.4 RxJava Observable（函数式观察者）

```kotlin
// Observable = 被观察的数据源
repository.getUser(userId)
    .subscribeOn(Schedulers.io())         // 订阅线程
    .observeOn(AndroidSchedulers.mainThread()) // 观察线程
    .map { user -> user.toPresentation() }
    .subscribe(
        onNext = { user -> updateUI(user) },
        onError = { error -> showError(error) },
        onComplete = { }
    )
    .addTo(compositeDisposable)  // 管理订阅生命周期
```

## 3. 责任链模式（Chain of Responsibility）

### 核心原理

**将请求沿着一条链传递，直到某个处理者处理为止。**

### Android 常见应用

#### 3.1 事件分发机制（View 触摸事件）

```kotlin
// 责任链：Activity → ViewGroup → View

class MyViewGroup(context: Context) : ViewGroup(context) {
    override fun dispatchTouchEvent(event: MotionEvent): Boolean {
        return super.dispatchTouchEvent(event)
        // 内部逻辑：
        // 1. 调用 onInterceptTouchEvent()
        // 2. 传递给子 View 的 dispatchTouchEvent()
        // 3. 如果子 View 返回 false，继续下一个子 View
    }
    
    override fun onInterceptTouchEvent(event: MotionEvent): Boolean {
        // 拦截器：决定是否拦截事件
        return false  // false = 传递给子 View；true = 自己处理
    }
    
    override fun onTouchEvent(event: MotionEvent): Boolean {
        // 最后的处理者
        return super.onTouchEvent(event)
    }
}
```

**事件分发链路**：

```
Activity.dispatchTouchEvent()
    ↓ (传递给根 ViewGroup)
ViewGroup.dispatchTouchEvent()
    ├─ onInterceptTouchEvent() → true: 拦截
    │   ↓
    │   onTouchEvent() → 处理事件
    │
    └─ onInterceptTouchEvent() → false: 传递
        ↓
        子 View.dispatchTouchEvent()
            ├─ onTouchEvent() → true: 消费
            └─ onTouchEvent() → false: 继续传递
```

#### 3.2 OkHttp 拦截器链

```kotlin
// OkHttp = 标准责任链实现

val httpClient = OkHttpClient.Builder()
    .addInterceptor(LoggingInterceptor())      // 第一个处理者
    .addInterceptor(AuthInterceptor())         // 第二个处理者
    .addNetworkInterceptor(HeaderInterceptor()) // 最后的处理者
    .build()

// 自定义拦截器
class AuthInterceptor : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val originalRequest = chain.request()
        
        // 前置处理：添加认证头
        val authenticatedRequest = originalRequest.newBuilder()
            .header("Authorization", "Bearer $token")
            .build()
        
        // 传递给链中的下一个拦截器
        val response = chain.proceed(authenticatedRequest)
        
        // 后置处理：检查 401 刷新 token
        if (response.code == 401) {
            val newToken = refreshToken()
            // 重试请求
            return intercept(
                object : Interceptor.Chain {
                    override fun request() = authenticatedRequest
                    override fun proceed(request: Request) = chain.proceed(
                        request.newBuilder()
                            .header("Authorization", "Bearer $newToken")
                            .build()
                    )
                }
            )
        }
        
        return response
    }
}
```

**OkHttp 内部链式调用**：

```kotlin
// RealInterceptorChain 源码简化
class RealInterceptorChain(
    private val interceptors: List<Interceptor>,
    private val index: Int
) : Interceptor.Chain {
    
    override fun proceed(request: Request): Response {
        if (index >= interceptors.size) {
            throw AssertionError("No more interceptors")
        }
        
        // 创建下一个链对象
        val next = RealInterceptorChain(interceptors, index + 1)
        val interceptor = interceptors[index]
        
        // 当前拦截器处理，内部调用 chain.proceed()
        return interceptor.intercept(next)
    }
}

// 调用链：
// Interceptor[0].intercept(Chain[0])
//   ↓ chain.proceed()
// Interceptor[1].intercept(Chain[1])
//   ↓ chain.proceed()
// Interceptor[2].intercept(Chain[2])
//   ↓ chain.proceed()
// RealHttpEngine.proceed() [真正发送网络请求]
```

#### 3.3 Window 事件分发

```kotlin
// Activity → Window → DecorView → 责任链

class Activity {
    private lateinit var mWindow: Window
    
    override fun dispatchTouchEvent(event: MotionEvent): Boolean {
        // 传递给 Window
        if (mWindow.superDispatchTouchEvent(event)) {
            return true
        }
        
        // Window 没处理，自己处理
        return onTouchEvent(event)
    }
}

// Window 内部
class PhoneWindow : Window {
    override fun superDispatchTouchEvent(event: MotionEvent): Boolean {
        // 传递给 DecorView（根 ViewGroup）
        return mDecor.superDispatchTouchEvent(event)
    }
}
```

#### 3.4 权限申请链（Runtime Permissions）

```kotlin
// 虽然不是严格的责任链，但展示处理流程

class PermissionHandler {
    private val handlers = mutableListOf<PermissionProcessor>()
    
    fun addHandler(handler: PermissionProcessor) {
        handlers.add(handler)
    }
    
    suspend fun requestPermission(permission: String) {
        for (handler in handlers) {
            if (handler.canHandle(permission)) {
                handler.process(permission)
                return
            }
        }
    }
}

interface PermissionProcessor {
    fun canHandle(permission: String): Boolean
    suspend fun process(permission: String)
}
```

## 核心对比

|模式|应用场景|关键特性|防护机制|
|---|---|---|---|
|**单例**|全局唯一资源|唯一性、全局访问|ThreadLocal、DCL|
|**观察者**|数据变化通知|发布-订阅、事件驱动|自动取消、生命周期感知|
|**责任链**|逐级处理请求|灵活流程、可扩展|链式调用、前后处理|
