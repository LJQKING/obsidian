
### 一、Handler是什么

**Handler** 是 Android 消息处理机制（**Handler、Looper、MessageQueue**）的核心组成部分。它最核心的作用是**将任务切换到指定的线程中执行**。

简单来说，Handler 是 Android 提供的 **“线程间通信桥梁”**。由于 Android 的 UI 线程（主线程）不允许被阻塞，且非 UI 线程不能直接更新 UI，因此我们需要 Handler 将子线程中的数据发送到主线程去更新界面。

- **本质**：它不是四大组件，而是一个 **Java 类**，配合底层 Linux 的 epoll（通过 Native 层）实现线程间的消息调度。
- **核心组件关系**：
  - **Message（消息）**：承载数据的载体。
  - **MessageQueue（消息队列）**：存放 Message 的容器，**先进先出（FIFO）**。
  - **Looper（循环器）**：负责无限循环从 MessageQueue 中取出 Message，并分发给 Handler。
  - **Handler（处理器）**：负责发送 Message 和处理 Message。

### 二、主要使用方式及区别

Handler 不涉及“启动”，但它的 **创建方式、消息发送方式、消息分发优先级** 存在明显区别。

#### 1. 创建方式（Looper 来源区别）

| 创建方式 | 代码示例 | Looper 来源 | 适用场景 | 关键风险 |
| :--- | :--- | :--- | :--- | :--- |
| **无参构造（已废弃）** | `new Handler()` | 隐式获取**当前线程**的 Looper | 在 UI 线程中创建（更新 UI） | **极易造成内存泄漏**（内部类持有外部类引用），且代码混淆后可能出错 |
| **指定 Looper** | `new Handler(Looper.myLooper())` | 显式传入特定线程的 Looper | 在子线程中创建 Handler，或需绑定主线程 | 必须确保传入的 Looper 已执行 `prepare()` |
| **主线程 Handler** | `new Handler(Looper.getMainLooper())` | 强制绑定**主线程（UI 线程）** | 在任意线程中都能安全地更新 UI | 处理耗时逻辑会阻塞 UI，造成 ANR |
| **HandlerThread** | `HandlerThread ht = ...; new Handler(ht.getLooper())` | 绑定**自带消息循环的子线程** | 需要长时间运行后台任务的场景（如轮询） | 不需要时需调用 `quit()` 停止线程 |

> **Android 开发规范**：自 API 30（Android 11）起，无参构造方法已被标记为 `deprecated`，强制开发者显式传入 Looper，避免隐式获取导致的风险。

#### 2. 发送消息方式（`post()` vs `sendMessage()`）

| 方式 | 使用场景 | 本质区别 |
| :--- | :--- | :--- |
| **`post(Runnable)`** | 想直接执行一段代码，不涉及数据传递 | 系统会将 `Runnable` 包装成 `Message`（`Message.callback = runnable`），最终在 `handleMessage` 中直接执行 `run()` |
| **`sendMessage(Message)`** | 需要传递大量数据（通过 `Bundle` 或 `arg`） | 开发者自定义 `Message` 对象，在 `handleMessage()` 中通过 `msg.what` 区分事件，再解析数据 |
| **`sendEmptyMessage(int what)`** | 仅需事件标识，无需携带数据 | 专门用于只传递 `what` 值的轻量场景 |

**总结**：`post()` 更适合“纯动作”，`sendMessage()` 更适合“带数据的事件”。

#### 3. 消息分发优先级（`dispatchMessage` 的执行顺序）

当 Handler 收到一个 Message 时，分发的**优先级从高到低**如下：

1. **`Message.callback`（最高）**：即 `post(Runnable)` 中的 `Runnable` 对象。
2. **`Handler.mCallback`（次之）**：通过 `new Handler(Callback)` 构造时传入的回调接口。若此接口返回 `true`，则拦截消息，不再执行 `handleMessage`。
3. **`Handler.handleMessage()`（最低）**：我们通常重写的空方法，作为最后的兜底处理。

#### 4. 消息类型（同步屏障与异步消息）

- **普通消息**：按入队时间顺序执行。
- **异步消息**：无需等待前面的普通消息，可被优先处理（常见于 `ViewRootImpl` 的 UI 绘制事件）。
- **同步屏障消息（Barrier）**：通过 `MessageQueue.postSyncBarrier()` 插入。当队列头部是屏障时，Looper 会跳过所有普通消息，只执行异步消息，直到屏障被移除。这保证了 UI 绘制等高优先级任务的及时响应。

### 三、具体场景代码实现

#### 场景一：子线程执行耗时任务，更新 UI（主线程 Handler）

这是最经典的使用方式，利用 Handler 将结果从子线程抛回主线程。

```java
public class MainActivity extends AppCompatActivity {
    // 推荐使用静态内部类 + WeakReference 防止内存泄漏
    private static class UIHandler extends Handler {
        private final WeakReference<MainActivity> mActivityRef;
        public UIHandler(MainActivity activity) {
            super(Looper.getMainLooper()); // 显式绑定主线程
            mActivityRef = new WeakReference<>(activity);
        }

        @Override
        public void handleMessage(@NonNull Message msg) {
            MainActivity activity = mActivityRef.get();
            if (activity == null) return;
            if (msg.what == 1) {
                String result = msg.getData().getString("data");
                activity.textView.setText(result); // 安全更新 UI
            }
        }
    }

    private UIHandler handler = new UIHandler(this);
    private TextView textView;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
        textView = findViewById(R.id.textView);

        new Thread(() -> {
            // 模拟耗时操作
            try { Thread.sleep(2000); } catch (InterruptedException e) {}
            String result = "下载完成";
            
            // 发送消息到主线程
            Message msg = Message.obtain();
            msg.what = 1;
            Bundle bundle = new Bundle();
            bundle.putString("data", result);
            msg.setData(bundle);
            handler.sendMessage(msg);
        }).start();
    }
}
```

#### 场景二：使用 HandlerThread 实现后台任务队列

HandlerThread 自带 Looper，适合串行处理多个后台任务。

```java
public class BackgroundService extends Service {
    private HandlerThread handlerThread;
    private Handler backgroundHandler;

    @Override
    public void onCreate() {
        super.onCreate();
        // 创建并启动 HandlerThread
        handlerThread = new HandlerThread("BackThread");
        handlerThread.start();
        // 将 Handler 绑定到该子线程的 Looper
        backgroundHandler = new Handler(handlerThread.getLooper()) {
            @Override
            public void handleMessage(@NonNull Message msg) {
                // 这里运行在子线程，适合执行 I/O 或数据库操作
                Log.d("Back", "执行任务: " + msg.what);
                // 注意：切勿在子线程中直接更新 UI
            }
        };
    }

    // 外部调用此方法即可向后台队列添加任务
    public void enqueueTask(int taskId) {
        backgroundHandler.sendEmptyMessage(taskId);
    }

    @Override
    public void onDestroy() {
        super.onDestroy();
        // 释放 Looper 和线程
        handlerThread.quitSafely();
    }
}
```

### 四、实现原理（核心机制）

Handler 的工作机制是一个经典的 **“生产者-消费者”** 模型，底层依赖 Linux 的 `epoll` 机制（通过 Native 层 `Looper` 实现）来实现线程阻塞与唤醒。

#### 1. 消息入队（生产）
当我们调用 `handler.sendMessage(msg)` 时，最终会走到 `MessageQueue.enqueueMessage()`：
- 将 `Message.target` 指向当前的 `Handler`（确保 Looper 知道由谁处理）。
- 根据 `when`（延迟时间）将消息插入到 **按时间排序的链表** 中。
- 如果消息位于队列头部，则调用 Native 层的 `nativeWake()` 唤醒正在阻塞的 `Looper`。

#### 2. 消息轮询（消费）
线程通过 `Looper.loop()` 进入无限循环：
- 调用 `MessageQueue.next()` 取出下一条消息。
- 如果队列为空，或没有到执行时间的消息，`next()` 会调用 `nativePollOnce()`（Native 层方法）。该方法会阻塞当前线程，直到被 `nativeWake()` 唤醒，或超时。
- **关键点**：`nativePollOnce()` 是阻塞，**不是 CPU 空转**，它利用 Linux epoll 机制让出 CPU 资源，因此不会导致应用卡顿或 CPU 占用飙升。

#### 3. 消息分发（处理）
`Looper.loop()` 拿到 Message 后，调用 `msg.target.dispatchMessage(msg)`：
- 回到我们第二点提到的分发优先级逻辑。
- 处理完成后，通过 `Message.recycleUnchecked()` 回收 `Message` 对象，将其放入全局的 **消息池（sPool）** 中复用，减少内存频繁分配。

#### 4. 内存泄漏原理（Why?）
非静态内部类（或匿名类）的 Handler 默认持有外部 Activity 的强引用。Activity 销毁时，若 MessageQueue 中仍有未处理的延迟 Message（持有 Handler 引用，Handler 持有 Activity 引用），导致 Activity 无法被 GC 回收，引发泄漏。

### 五、重要补充与注意事项

- **`IdleHandler` 机制**：当 `MessageQueue` 暂时没有消息需要处理时（即 CPU 空闲），会执行通过 `MessageQueue.addIdleHandler()` 添加的回调。可用于在界面完全绘制完成后再执行次要任务（如预加载）。
- **主线程的死循环疑问**：为什么主线程的 `Looper.loop()` 是死循环却没有 ANR？因为 `next()` 在没有消息时会通过 `epoll` 阻塞，一旦有输入事件、Binder 调用或 Handler 消息，内核会唤醒它。ANR 发生的原因是 **消息处理时间过长**（如 `onClick` 里执行了 5 秒的 `sleep`），而非 Looper 循环本身。
- **`postDelayed` 的精确度**：`postDelayed` 并非精确的定时器。它只是将消息的 `when` 设置为当前时间 + 延迟时间。如果队列头部有耗时消息阻塞，后续的延迟消息会被顺延执行。
- **子线程创建 Handler 的步骤**：在子线程中创建 Handler，必须先调用 `Looper.prepare()` 创建该线程的消息队列，否则会抛出 `Can't create handler inside thread that has not called Looper.prepare()`。HandlerThread 已经帮我们封装了这一步。
