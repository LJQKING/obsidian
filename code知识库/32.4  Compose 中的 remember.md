`remember` 是 Jetpack Compose 中用于在 **Recomposition（重组）** 过程中保持状态不变的关键函数。它的核心职责是：在组件重新绘制时，保留之前计算或存储的值，而不是每次都重新计算。

```kotlin
@Composable
fun rememberSomeValue(): SomeType {
    return remember {
        // 这个代码块只会执行一次（第一次组合时）
        computeExpensiveValue()
    }
}
```

---

## 工作原理

### 1. **Recomposition 与内存问题**

Compose 中的 `@Composable` 函数会频繁被重新调用，特别是当：

- 状态改变
- 父组件重组
- 参数改变

**问题**：如果没有 `remember`，每次 Recomposition 都会重新执行函数体中的代码。

```kotlin
@Composable
fun BadExample() {
    val random = Random.nextInt()  // ❌ 每次重组都会生成新值
    Text(random.toString())
}
```

### 2. **`remember` 的缓存机制**

`remember` 会：

- **第一次组合**：执行 lambda，返回计算结果，**缓存到 Compose 的内存树中**
- **Recomposition**：从缓存中取值，**不再执行 lambda**
- **离开作用域**：自动释放缓存

```kotlin
@Composable
fun GoodExample() {
    val random = remember {
        Random.nextInt()  // ✅ 只执行一次
    }
    Text(random.toString())
}
```

### 3. **与 State 的配合**

`remember` 通常与 `mutableStateOf` 结合，创建可变状态：

```kotlin
@Composable
fun Counter() {
    val count = remember { mutableStateOf(0) }
    
    Button(onClick = { count.value++ }) {
        Text("Count: ${count.value}")
    }
}
```

---

## 原理细节：Compose 的执行流程

```
1. Initial Composition（首次组合）
   ├─ 执行 remember { ... } 的 lambda
   ├─ 结果存入内存树（Backing Map）
   └─ 返回值给组件

2. Recomposition（重组）
   ├─ 比较输入参数
   ├─ 如果 remember 的 key 相同
   │  └─ 直接从缓存取值 ✅（不再计算）
   └─ 如果 key 改变
      └─ 重新计算新值

3. Disposal（销毁）
   └─ 组件离开作用域时，缓存自动清理
```

## 实际使用例子

### 例 1：保存计算结果

```kotlin
@Composable
fun ExpensiveCalculation() {
    val expensiveList = remember {
        (1..1000).map { it * it }  // 只计算一次
    }
    
    LazyColumn {
        items(expensiveList) { value ->
            Text("$value")
        }
    }
}
```

### 例 2：保存 UI 状态

```kotlin
@Composable
fun FormScreen() {
    val nameState = remember { mutableStateOf("") }
    val ageState = remember { mutableStateOf(0) }
    
    TextField(
        value = nameState.value,
        onValueChange = { nameState.value = it }
    )
    TextField(
        value = ageState.value.toString(),
        onValueChange = { ageState.value = it.toIntOrNull() ?: 0 }
    )
}
```

### 例 3：保存对象引用（防止 Lambda 重新创建）

```kotlin
@Composable
fun ClickableButton() {
    // ❌ 不好：每次重组都创建新的 lambda
    Button(onClick = { println("Clicked") }) {
        Text("Click me")
    }
    
    // ✅ 好：缓存 lambda，防止子组件重复重组
    val onClickAction = remember {
        { println("Clicked") }
    }
    Button(onClick = onClickAction) {
        Text("Click me")
    }
}
```

### 例 4：带 Key 的 `remember`（依赖项改变时重新计算）

```kotlin
@Composable
fun UserProfile(userId: String) {
    val userData = remember(userId) {
        // userId 改变时，重新加载用户数据
        loadUserData(userId)
    }
    
    Text("User: ${userData.name}")
}
```

**关键**：`remember(key1, key2, ...)` 中的 key 改变时，会重新执行 lambda。

## 常见模式

### 模式 1：使用 `rememberSaveable`（进程死亡也能恢复）

```kotlin
@Composable
fun PersistentCounter() {
    val count = rememberSaveable { mutableStateOf(0) }
    
    Button(onClick = { count.value++ }) {
        Text("Count: ${count.value}")  // 屏幕旋转后仍保留
    }
}
```

### 模式 2：派生状态（DerivedState）

```kotlin
@Composable
fun HighlightedList(items: List<String>) {
    val selectedIndex = remember { mutableStateOf(0) }
    
    // 只在 selectedIndex 改变时重新计算
    val selectedItem by remember {
        derivedStateOf { items.getOrNull(selectedIndex.value) }
    }
    
    Text("Selected: $selectedItem")
}
```

### 模式 3：防止不必要的重新调用（使用 `rememberCoroutineScope`）

```kotlin
@Composable
fun AsyncDataLoader() {
    val scope = rememberCoroutineScope()
    
    Button(onClick = {
        scope.launch {
            val data = fetchData()  // 协程作用域重用
            // 更新 UI
        }
    }) {
        Text("Load Data")
    }
}
```

## 性能对比

```kotlin
// ❌ 性能差：每次重组都重新创建 list
@Composable
fun BadList() {
    val items = (1..100).map { "Item $it" }
    LazyColumn {
        items(items) { item -> Text(item) }
    }
}

// ✅ 性能好：list 被缓存
@Composable
fun GoodList() {
    val items = remember { (1..100).map { "Item $it" } }
    LazyColumn {
        items(items) { item -> Text(item) }
    }
}
```

## 面试要点总结

|概念|说明|
|---|---|
|**用途**|在 Recomposition 中保留状态/计算结果|
|**缓存位置**|Compose 的内存树（Backing Map）|
|**触发清理**|组件离开 Composable 树时|
|**`remember` + Key**|Key 改变时重新计算|
|**`rememberSaveable`**|支持进程死亡恢复（Bundle 序列化）|
|**常见误区**|不用 `remember` 导致频繁重新计算|
