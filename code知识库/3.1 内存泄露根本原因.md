**一句话本质：** 生命周期短的对象，被生命周期长的对象持有引用，导致 GC 无法回收。
## 核心机制

```
GC Roots
   │
   └── 长生命周期对象 ──────────────── 持有引用
                                         │
                                         ▼
                               短生命周期对象（本该被回收）
                               ← Activity / Fragment / View
                               ← Context
                               ← Bitmap
```

GC 的判断标准是**可达性**，只要从 GC Roots 出发能找到该对象，就不会回收。

---

## 六大根因分类

### 1. 静态变量持有 Context / View

```kotlin
companion object {
    var instance: MyActivity? = null  // ❌ Activity 永远无法回收
    var view: View? = null            // ❌ View 持有 Activity 引用
}
```

**根因**：静态变量属于 Class 级别，生命周期 = 进程生命周期。

---

### 2. 内部类 / 匿名类隐式持有外部类引用

```kotlin
class MyActivity : Activity() {

    // ❌ Handler 是非静态内部类，隐式持有 Activity.this
    val handler = object : Handler(Looper.getMainLooper()) {
        override fun handleMessage(msg: Message) { ... }
    }

    fun leak() {
        // ❌ Runnable 匿名类同理
        handler.postDelayed({ doSomething() }, 60_000)
    }
}
```

**根因**：JVM 非静态内部类编译后会自动保存外部类 `this` 引用（`this$0`）。

**修复**：

```kotlin
// 静态内部类 + WeakReference
class SafeHandler(activity: MyActivity) : Handler(Looper.getMainLooper()) {
    private val ref = WeakReference(activity)
    override fun handleMessage(msg: Message) {
        ref.get()?.doSomething()
    }
}
```

---

### 3. 单例持有 Context

```kotlin
object NetworkManager {
    // ❌ 如果传入 Activity Context，Activity 永远泄露
    lateinit var context: Context
}
```

**根因**：单例生命周期 = 进程，Activity 生命周期 = 页面。

**修复**：永远使用 `applicationContext`。

---

### 4. 集合类未清理

```kotlin
object Cache {
    val list = mutableListOf<Bitmap>()  // ❌ 不断添加，从不移除
    val map = HashMap<String, Any>()    // ❌ 同上
}
```

**根因**：集合本身是 GC Root 可达的，它持有的对象永远无法回收。

---

### 5. 注册/订阅未反注册

```kotlin
// ❌ 这些都会持有 Activity/Fragment 引用
registerReceiver(receiver, filter)      // BroadcastReceiver
EventBus.getDefault().register(this)    // EventBus
liveData.observe(this, observer)        // LiveData（需传 lifecycleOwner）
rxDisposable = observable.subscribe()   // RxJava
```

**根因**：系统/框架内部维护的 Observer 列表（GC Root 可达）持有了你的对象。

---

### 6. 资源未关闭

```kotlin
// ❌ Cursor / Stream / DB 未关闭，持有底层 native 内存
val cursor = db.rawQuery(sql, null)
// 忘记 cursor.close()
```

**根因**：Java 对象背后往往有 Native 层资源，GC 只管 Java 堆，native 内存不受 GC 管辖。

---

## 车机场景特有根因

|场景|泄露点|
|---|---|
|VHAL 回调|`CarPropertyManager.registerCallback()` 未 `unregister`，持有 Fragment|
|跨域通信|AIDL `linkToDeath` 注册 `DeathRecipient` 后 Activity 销毁未清理|
|大 Bitmap 导航地图|静态缓存 Bitmap 未释放，占用大量 native 内存|
|SystemService 订阅|`AudioManager` / `SensorManager` listener 未移除|

---

## 判断是否泄露：三个问题

```
1. 谁持有了这个对象的引用？
2. 持有者的生命周期比这个对象长吗？
3. 在对象该销毁时，这个引用会被切断吗？
```

三个问题中任何一个答案为"不确定"，就需要检查。
