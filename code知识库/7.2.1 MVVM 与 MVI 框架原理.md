
## MVVM (Model-View-ViewModel)

### 核心原理

MVVM 是由 **Model**、**View** 和 **ViewModel** 三层组成的架构模式，强调 **数据驱动 UI**：

```
┌─────────────┐
│    View     │ (Activity/Fragment/Compose)
│  (UI Layer) │
└──────┬──────┘
       │ 观察 LiveData/StateFlow
       │
┌──────▼─────────────────┐
│    ViewModel           │ (业务逻辑层)
│  - 持有 StateFlow      │
│  - 暴露 UI 状态        │
│  - 处理用户交互        │
└──────┬─────────────────┘
       │ 查询/更新数据
       │
┌──────▼──────────────────┐
│   Model (Repository)    │ (数据层)
│ - Room/数据库           │
│ - 网络请求              │
│ - SharedPreferences     │
└─────────────────────────┘
```

### 关键特性

1. **单向数据绑定**：View 观察 ViewModel 中的 StateFlow/LiveData
2. **ViewModel 生命周期独立**：存活于 Activity/Fragment 配置变化之间
3. **不持有 View 引用**：ViewModel 不知道 View 的存在（解耦）
4. **状态管理**：UI 状态集中在 ViewModel 中

### MVVM 代码示例

```kotlin
// ViewModel 层
class UserViewModel(private val repo: UserRepository) : ViewModel() {
    private val _userState = MutableStateFlow<UiState>(UiState.Loading)
    val userState: StateFlow<UiState> = _userState.asStateFlow()
    
    fun loadUser(userId: String) {
        viewModelScope.launch {
            try {
                val user = repo.getUser(userId)
                _userState.value = UiState.Success(user)
            } catch (e: Exception) {
                _userState.value = UiState.Error(e.message)
            }
        }
    }
}

sealed class UiState {
    object Loading : UiState()
    data class Success(val user: User) : UiState()
    data class Error(val message: String?) : UiState()
}

// View 层 (Compose)
@Composable
fun UserScreen(viewModel: UserViewModel = hiltViewModel()) {
    val userState by viewModel.userState.collectAsStateWithLifecycle()
    
    when (userState) {
        is UiState.Loading -> LoadingIndicator()
        is UiState.Success -> UserContent((userState as UiState.Success).user)
        is UiState.Error -> ErrorMessage((userState as UiState.Error).message)
    }
    
    LaunchedEffect(Unit) {
        viewModel.loadUser("123")
    }
}
```

## MVI (Model-View-Intent)

### 核心原理

MVI 是单向数据流架构，强调 **Intent → State → Render** 的循环：

```
┌─────────────────────────┐
│        View             │
│  (User Interaction)     │
└──────────┬──────────────┘
           │ emit Intent
           │
┌──────────▼──────────────┐
│      ViewModel          │
│  (Presenter/Reducer)    │
│  - 处理 Intent          │
│  - 计算新 State         │
└──────────┬──────────────┘
           │ emit new State
           │
┌──────────▼──────────────┐
│        View             │
│  (Render UI from State) │
└─────────────────────────┘
           △
           │ 用户交互
           │
        └──┘ 循环
```

### 关键特性

1. **单向数据流**：Intent → Processor → State → View
2. **不可变状态**：每个 State 是完整的 UI 状态快照
3. **函数式编程**：`State reducer(previousState, intent)`
4. **可追踪性**：所有状态变化都来自明确的 Intent，便于调试和重放

### MVI 代码示例

```kotlin
// Intent 定义
sealed class UserIntent {
    data class LoadUser(val userId: String) : UserIntent()
    object Refresh : UserIntent()
    data class UpdateName(val newName: String) : UserIntent()
}

// 完整的 UI 状态
data class UserViewState(
    val loading: Boolean = false,
    val user: User? = null,
    val error: String? = null
)

// ViewModel (处理 Intent 和状态转换)
class UserViewModel(private val repo: UserRepository) : ViewModel() {
    
    // 接收 Intent
    fun processIntent(intent: UserIntent) {
        when (intent) {
            is UserIntent.LoadUser -> loadUser(intent.userId)
            is UserIntent.Refresh -> refresh()
            is UserIntent.UpdateName -> updateName(intent.newName)
        }
    }
    
    // 存储完整状态
    private val _viewState = MutableStateFlow(UserViewState())
    val viewState: StateFlow<UserViewState> = _viewState.asStateFlow()
    
    // Reducer 模式：旧状态 + Intent → 新状态
    private fun reduce(newState: UserViewState) {
        _viewState.value = newState
    }
    
    private fun loadUser(userId: String) {
        viewModelScope.launch {
            // 设置 Loading 状态
            reduce(_viewState.value.copy(loading = true, error = null))
            
            try {
                val user = repo.getUser(userId)
                // 成功状态
                reduce(_viewState.value.copy(
                    loading = false,
                    user = user,
                    error = null
                ))
            } catch (e: Exception) {
                // 错误状态
                reduce(_viewState.value.copy(
                    loading = false,
                    error = e.message
                ))
            }
        }
    }
    
    private fun refresh() {
        loadUser(_viewState.value.user?.id ?: "")
    }
    
    private fun updateName(newName: String) {
        val currentUser = _viewState.value.user ?: return
        reduce(_viewState.value.copy(
            user = currentUser.copy(name = newName)
        ))
    }
}

// View 层
@Composable
fun UserScreen(viewModel: UserViewModel = hiltViewModel()) {
    val state by viewModel.viewState.collectAsStateWithLifecycle()
    
    Column {
        when {
            state.loading -> LoadingIndicator()
            state.error != null -> ErrorMessage(state.error)
            state.user != null -> {
                UserContent(state.user!!)
                Button(onClick = {
                    viewModel.processIntent(UserIntent.Refresh)
                }) {
                    Text("刷新")
                }
            }
        }
    }
    
    LaunchedEffect(Unit) {
        viewModel.processIntent(UserIntent.LoadUser("123"))
    }
}
```

## MVVM vs MVI 对比

|特性|MVVM|MVI|
|---|---|---|
|**数据流方向**|双向（观察者模式）|单向循环|
|**状态结构**|多个独立的 StateFlow|单个完整的 ViewState|
|**用户交互处理**|直接调用 ViewModel 方法|通过 Intent 发送|
|**状态变化**|可变更新各个字段|每次产生全新 State|
|**调试可追踪性**|中等（多个变化源）|优秀（所有变化来自 Intent）|
|**学习曲线**|平缓|陡峭|
|**适用场景**|简单/中等复杂业务|复杂、状态多变的场景|
|**性能**|更新细粒度（更优）|每次产生全新对象|
|**代码量**|较少|较多（Intent 定义等）|

---

在智能座舱开发中：

- **MVVM** 适合单一功能模块（如导航、音乐播放器）
- **MVI** 更适合系统级应用（多源 Intent：语音、触摸、CarPropertyManager 回调）

## MVVM 框架原理

**MVVM（Model-View-ViewModel）** 的核心是通过 **ViewModel** 作为 View 与 Model 之间的桥梁，实现数据绑定。

```
Model ↔ ViewModel ↔ View
        (数据绑定)
```

### 核心机制

1. **Model**：业务逻辑和数据源（Repository、数据库、网络）
2. **ViewModel**：持有 UI 所需的数据状态，通常暴露为 `LiveData` 或 `StateFlow`
3. **View**：Android 的 Activity/Fragment，观察 ViewModel 中的数据变化

### 代码示例

```kotlin
// ViewModel
class UserViewModel(private val userRepository: UserRepository) : ViewModel() {
    private val _userLiveData = MutableLiveData<User>()
    val userLiveData: LiveData<User> = _userLiveData

    fun loadUser(id: String) {
        viewModelScope.launch {
            val user = userRepository.getUser(id)
            _userLiveData.value = user
        }
    }
}

// View
class UserActivity : AppCompatActivity() {
    private val viewModel: UserViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        viewModel.userLiveData.observe(this) { user ->
            // 直接更新 UI
            textName.text = user.name
        }
        
        viewModel.loadUser("123")
    }
}
```

### MVVM 的特点

- **被动更新**：ViewModel 暴露数据，View 被动观察
- **双向绑定**：数据变化推送给 View（但 View 主动订阅）
- **状态管理**：ViewModel 本身就是状态容器
- **易于测试**：ViewModel 不依赖 Android 组件

## MVI 框架原理

**MVI（Model-View-Intent）** 的核心是 **单向数据流**，所有用户交互都转化为 **Intent**，通过纯函数的状态转移产生新的 **State**。

```
Intent → ViewModel → State → View → User Action
  ↑                             ↓
  └─────────────────────────────┘
      (单向循环数据流)
```

### 核心机制

1. **Model**：纯数据模型（通常就是 State）
2. **View**：被动展示 State，主动发送 Intent（用户意图）
3. **Intent**：所有用户交互的表示（点击、输入、加载等）
4. **Reducer**：纯函数，根据 Intent 和当前 State 计算新 State

### 代码示例

```kotlin
// 定义 Intent（用户意图）
sealed class UserIntent {
    data class LoadUser(val id: String) : UserIntent()
    object Retry : UserIntent()
}

// 定义 State（UI 状态）
data class UserState(
    val loading: Boolean = false,
    val user: User? = null,
    val error: String? = null
)

// ViewModel - 单向数据流处理器
class UserViewModel(private val userRepository: UserRepository) : ViewModel() {
    private val _stateFlow = MutableStateFlow(UserState())
    val stateFlow: StateFlow<UserState> = _stateFlow.asStateFlow()

    fun processIntent(intent: UserIntent) {
        when (intent) {
            is UserIntent.LoadUser -> {
                viewModelScope.launch {
                    _stateFlow.value = _stateFlow.value.copy(loading = true)
                    try {
                        val user = userRepository.getUser(intent.id)
                        _stateFlow.value = UserState(user = user, error = null)
                    } catch (e: Exception) {
                        _stateFlow.value = UserState(error = e.message)
                    }
                }
            }
            is UserIntent.Retry -> processIntent(UserIntent.LoadUser("123"))
        }
    }
}

// View - 被动接收 State，主动发送 Intent
class UserActivity : AppCompatActivity() {
    private val viewModel: UserViewModel by viewModels()

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        lifecycleScope.launchWhenStarted {
            viewModel.stateFlow.collect { state ->
                when {
                    state.loading -> progressBar.visibility = View.VISIBLE
                    state.user != null -> {
                        textName.text = state.user.name
                        progressBar.visibility = View.GONE
                    }
                    state.error != null -> showError(state.error)
                }
            }
        }
        
        // 发送 Intent
        viewModel.processIntent(UserIntent.LoadUser("123"))
    }
}
```

## 根本区别对比

|维度|MVVM|MVI|
|---|---|---|
|**数据流方向**|双向（View ↔ ViewModel）|单向（Intent → State → View）|
|**状态表示**|ViewModel 持有多个 LiveData/StateFlow|单一 State 对象承载所有 UI 状态|
|**用户交互**|View 直接调用 ViewModel 方法|View 发送 Intent，ViewModel 响应 Intent|
|**状态转移**|分散在各个方法中|集中在 Reducer（纯函数）中|
|**可预测性**|中等（需要追踪多个数据源）|高（单一数据流，所有变化可追踪）|
|**复杂度**|低（适合简单业务）|高（适合复杂交互）|
|**测试**|简单（Mock ViewModel 方法）|容易（Intent → State 的映射是纯函数）|
|**调试**|相对困难（多数据源）|容易（完整状态历史记录）|
|**并发问题**|需要手动处理竞态条件|天然支持（所有变化序列化）|

## 核心设计理念的差异

### MVVM：对象驱动

```
- ViewModel 是对象，包含多个可变属性
- View 订阅关心的属性
- "我要得到数据" → ViewModel.getData()
```

### MVI：事件驱动

```
- 所有变化来自 Intent（事件）
- State 是数据的单一源头
- "我要做这个动作" → Intent.ActionX → reducer → 新 State
```

## 何时选择

- **MVVM**：
    
    - 功能简单（CRUD 操作）
    - 团队规模小
    - 快速原型开发
    - 状态变化不复杂
- **MVI**：
    
    - 复杂交互（多步骤流程、撤销重做等）
    - 需要完整状态追踪
    - 团队规模大
    - 高并发场景
    - 需要时间旅行调试（Redux DevTools）

MVI 本质上是**函数式反应型编程**的应用，而 MVVM 是**响应式对象编程**。前者更强调**可预测性和可测试性**，后者更强调**简洁性和易用性**。
