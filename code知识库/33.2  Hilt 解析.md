
## 1. 什么是 Hilt

- [[33 Hilt  Dagger  依赖注入.md]]  Hilt依赖注入
- [[33.0  Dagger2 完全解析.md]]  Hilt依赖注入
- [[33.1  Dagger2 vs Hilt 深度对比.md]]  Hilt依赖注入
**Hilt** 是 Google 官方推出的 Android 依赖注入框架，构建于 Dagger 2 之上。它的目标是**简化 Dagger 的使用复杂度**，提供更加便捷的依赖注入解决方案。

### 核心特点

- 基于 **APT（Annotation Processing Tool）** 的编译期代码生成
- 提供标准化的组件生命周期管理
- 与 Android 生命周期深度集成
- 自动生成 `Component` 和 `Module`

## 2. 核心原理

### 2.1 架构层次

```
┌─────────────────────────┐
│   @HiltAndroidApp       │  应用级别
│   (Application)         │
└────────────┬────────────┘
             │
    ┌────────┴────────┐
    │                 │
┌───▼───────────┐  ┌─▼────────────┐
│ @AndroidEntryPoint   │ @AndroidEntryPoint
│ (Activity/Fragment)  │ (Service/BroadcastReceiver)
└──────────────┘  └─────────────┘
    │                 │
    └────────┬────────┘
             │
       ┌─────▼──────┐
       │  Hilt生成的  │
       │  Component  │
       └─────┬──────┘
             │
       ┌─────▼─────────┐
       │ @Module 和实例 │
       └───────────────┘
```

### 2.2 编译期代码生成过程

```
┌──────────────────┐
│ 源代码中的注解   │
│ (@Hilt*)         │
└────────┬─────────┘
         │
    ┌────▼─────────────────────┐
    │ Hilt处理器                │
    │ (HiltProcessor)          │
    │ - 解析注解                │
    │ - 生成KAPT/APT代码       │
    │ - 创建Component          │
    └────┬─────────────────────┘
         │
    ┌────▼──────────────────────────┐
    │ 生成的文件（build目录）        │
    │ - Hilt_Application.java       │
    │ - ApplicationComponent.java   │
    │ - Activity_HiltComponents.java│
    └────┬──────────────────────────┘
         │
    ┌────▼──────────────────┐
    │ 编译成字节码          │
    │ (.class文件)          │
    └───────────────────────┘
```

## 3. 源码级实现分析

### 3.1 关键注解

```kotlin
// 1. 应用级别入口
@HiltAndroidApp
class MyApplication : Application() {
    // Hilt 会在编译期生成：Hilt_MyApplication
}

// 2. Activity/Fragment 注入入口
@AndroidEntryPoint
class MainActivity : AppCompatActivity() {
    @Inject lateinit var userRepository: UserRepository
    // Hilt生成中间类：MainActivity_MemberInjector
}

// 3. 服务组件
@AndroidEntryPoint
class MyService : Service() {
    @Inject lateinit var analyticsService: AnalyticsService
}

// 4. 依赖提供模块
@Module
@InstallIn(SingletonComponent::class)  // 指定生命周期
object RepositoryModule {
    
    @Provides
    @Singleton
    fun provideUserRepository(
        api: UserApi,
        database: AppDatabase
    ): UserRepository {
        return UserRepository(api, database)
    }
}
```

### 3.2 生成的源码示例

当你使用 `@Hilt*` 注解时，Hilt 生成的代码结构大致如下：

```java
// 生成的应用类包装器
public class Hilt_MyApplication extends MyApplication {
    
    private ApplicationComponent applicationComponent;
    
    @Override
    public void onCreate() {
        // 1. 创建ApplicationComponent
        this.applicationComponent = DaggerApplicationComponent
            .builder()
            .build();
        
        // 2. 注入应用级别依赖
        this.applicationComponent.injectMyApplication(this);
        
        super.onCreate();
    }
    
    ApplicationComponent getApplicationComponent() {
        return applicationComponent;
    }
}

// 生成的 Activity 注入器
public class MainActivity_MemberInjector {
    
    public static void injectUserRepository(
        MainActivity activity,
        UserRepository userRepository) {
        activity.userRepository = userRepository;
    }
}

// 生成的 Component（类似 Dagger Component）
@Singleton
@Component(
    modules = {
        RepositoryModule.class,
        DatabaseModule.class,
        // ... 其他Module
    }
)
public interface ApplicationComponent {
    void injectMyApplication(MyApplication app);
    void injectMainActivity(MainActivity activity);
}
```

### 3.3 关键类的职责

|类/接口|职责|生成时机|
|---|---|---|
|`SingletonComponent`|应用级别作用域|自动生成|
|`ActivityComponent`|Activity级别作用域|自动生成|
|`FragmentComponent`|Fragment级别作用域|自动生成|
|`@Module`|依赖提供逻辑|用户编写|
|`@Provides`|工厂方法标记|用户编写|
|`@EntryPoint`|在不支持注入的地方获取依赖|用户编写|

## 4. 实际应用场景

### 场景1：标准的分层架构注入

```kotlin
// 数据层
@Module
@InstallIn(SingletonComponent::class)
object DataModule {
    
    @Provides
    @Singleton
    fun provideRetrofit(): Retrofit {
        return Retrofit.Builder()
            .baseUrl("https://api.example.com")
            .addConverterFactory(GsonConverterFactory.create())
            .build()
    }
    
    @Provides
    @Singleton
    fun provideUserApi(retrofit: Retrofit): UserApi {
        return retrofit.create(UserApi::class.java)
    }
    
    @Provides
    @Singleton
    fun provideDatabase(context: Context): AppDatabase {
        return Room.databaseBuilder(
            context,
            AppDatabase::class.java,
            "app.db"
        ).build()
    }
}

// 仓储层
@Module
@InstallIn(SingletonComponent::class)
object RepositoryModule {
    
    @Provides
    @Singleton
    fun provideUserRepository(
        api: UserApi,
        database: AppDatabase
    ): UserRepository {
        return UserRepository(api, database.userDao())
    }
}

// 业务逻辑层
class UserViewModel @Inject constructor(
    private val userRepository: UserRepository
) : ViewModel() {
    
    fun fetchUsers() {
        // 使用注入的 repository
    }
}

// UI层
@AndroidEntryPoint
class UserActivity : AppCompatActivity() {
    
    private val viewModel: UserViewModel by viewModels()
    
    @Inject
    lateinit var analyticsService: AnalyticsService
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // userRepository 和 analyticsService 已自动注入
    }
}

// 应用入口
@HiltAndroidApp
class MyApplication : Application()
```

### 场景2：多实现的条件注入

```kotlin
// 接口定义
interface Logger {
    fun log(message: String)
}

// 多个实现
class ConsoleLogger @Inject constructor() : Logger {
    override fun log(message: String) = println(message)
}

class FileLogger @Inject constructor(context: Context) : Logger {
    override fun log(message: String) {
        // 写入文件
    }
}

// 使用 @Qualifier 区分
@Qualifier
@Retention(AnnotationRetention.BINARY)
annotation class ConsoleLog

@Qualifier
@Retention(AnnotationRetention.BINARY)
annotation class FileLog

// Module 中提供不同实现
@Module
@InstallIn(SingletonComponent::class)
object LoggerModule {
    
    @Provides
    @ConsoleLog
    fun provideConsoleLogger(): Logger = ConsoleLogger()
    
    @Provides
    @FileLog
    fun provideFileLogger(context: Context): Logger = FileLogger(context)
}

// 使用时
@AndroidEntryPoint
class MainActivity : AppCompatActivity() {
    
    @Inject @ConsoleLog
    lateinit var consoleLogger: Logger
    
    @Inject @FileLog
    lateinit var fileLogger: Logger
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        consoleLogger.log("Console message")  // 输出到控制台
        fileLogger.log("File message")        // 写入文件
    }
}
```

### 场景3：不同生命周期作用域

```kotlin
// Activity 级别作用域
@Qualifier
@Retention(AnnotationRetention.BINARY)
annotation class ActivityScope

// Fragment 级别作用域
@Qualifier
@Retention(AnnotationRetention.BINARY)
annotation class FragmentScope

@Module
@InstallIn(ActivityComponent::class)  // Activity 级别
object ActivityModule {
    
    @Provides
    @ActivityScope
    fun provideActivityViewModel(): ActivityViewModel {
        // 每个 Activity 创建一次
        return ActivityViewModel()
    }
}

@Module
@InstallIn(FragmentComponent::class)  // Fragment 级别
object FragmentModule {
    
    @Provides
    fun provideFragmentPresenter(): FragmentPresenter {
        // 每个 Fragment 创建一次
        return FragmentPresenter()
    }
}

@AndroidEntryPoint
class DetailFragment : Fragment() {
    
    @Inject
    lateinit var presenter: FragmentPresenter
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        // presenter 已注入，生命周期与 Fragment 一致
    }
}
```

### 场景4：在非注入类中获取依赖（EntryPoint）

```kotlin
// 定义 EntryPoint
@EntryPoint
@InstallIn(SingletonComponent::class)
interface AnalyticsEntryPoint {
    fun getAnalyticsService(): AnalyticsService
}

// 在没有 @AndroidEntryPoint 的地方使用
class NotDirectlyInjectableClass {
    
    fun sendAnalytics(context: Context) {
        // 通过 EntryPoint 获取依赖
        val entryPoint = EntryPointAccessors.fromApplication(
            context,
            AnalyticsEntryPoint::class.java
        )
        val analytics = entryPoint.getAnalyticsService()
        analytics.trackEvent("event_name")
    }
}
```

### 场景5：为第三方库提供依赖（@InstallIn）

// OkHttp 拦截器模块
@Module
@InstallIn(SingletonComponent::class)
object NetworkModule {

    @Singleton

## 5. 关键实现细节

### 5.1 Component 生命周期管理

```
Application启动
    ↓
@HiltAndroidApp 初始化
    ↓
ApplicationComponent (Singleton) 创建
    ↓
Activity 启动
    ↓
ActivityComponent 创建（包含 Activity 作用域实例）
    ↓
@AndroidEntryPoint 触发注入
    ↓
Fragment 创建
    ↓
FragmentComponent 创建（包含 Fragment 作用域实例）
    ↓
Activity 销毁
    ↓
ActivityComponent 销毁（释放 Activity 作用域实例）
    ↓
Application 销毁
    ↓
ApplicationComponent 销毁（释放 Singleton 实例）
```

### 5.2 编译期 vs 运行期

|阶段|操作|示例|
|---|---|---|
|**编译期**|APT 处理注解|`HiltProcessor` 解析 `@Hilt*`|
|**编译期**|生成代码|`Hilt_MyApplication.java`|
|**编译期**|生成 Component|`DaggerApplicationComponent`|
|**运行期**|应用启动|`@HiltAndroidApp` 初始化|
|**运行期**|Activity 创建|Component 注入依赖|
|**运行期**|对象释放|Scope 失效时清理|

## 6. 面试要点总结

|问题|核心答案|
|---|---|
|**Hilt vs Dagger2**|Hilt 封装了 Dagger2，提供自动化 Component 生成、标准化生命周期管理|
|**工作原理**|编译期 APT 解析注解→生成 Component 代码→运行期依赖注入|
|**性能影响**|编译期生成代码（无反射）→运行期零开销，比传统手动注入更快|
|**内存管理**|通过 Scope（Singleton/Activity/Fragment）自动管理生命周期|
|**常见问题**|Context 注入用 `@ApplicationContext`，避免内存泄漏|
