
## 一、ARouter 核心原理

### 1. 编译期：注解处理 + 路由表自动生成
开发者用 `@Route(path = "/test/main")` 标注页面或服务，编译时通过 **APT** 扫描所有 `@Route` 注解，生成如下辅助类：

- `ARouter$$Root$$<module>` – 注册分组信息
- `ARouter$$Group$$<group>` – 记录该分组下每个路径与目标 Class 的映射

例如生成的类会包含类似逻辑：
```java
public class ARouter$$Group$$test implements IRouteGroup {
  @Override
  public void loadInto(Map<String, RouteMeta> atlas) {
    atlas.put("/test/main", RouteMeta.build(RouteType.ACTIVITY, MainActivity.class, ...));
  }
}
```
这些类在编译阶段就已确定，实现路由表的静态化，避免运行时反射的大量使用。

### 2. 初始化：加载路由表到内存
`ARouter.init(application)` 调用时，框架会：
- 通过包名扫描加载所有 `ARouter$$Root$$` 类
- 延迟加载各分组的路由详情，放入 `Warehouse` 的 Map 中
- 初始化拦截器、IoC 注入等组件

路由表构建完成后，`/test/main` 对应的 `RouteMeta` 就可被快速查询到。

### 3. 跳转流程：Postcard → 寻址 → 跳转
调用流程：

```java
ARouter.getInstance().build("/test/main").navigation();
```

内部详细步骤：
1. **构建 Postcard**：`build(path)` 创建一个明信片对象，包含路径、参数、跳转动画、Bundle 等。
2. **完善信息（completion）**：`LogisticsCenter.completion(postcard)` 根据路径在 `Warehouse` 中查找 `RouteMeta`，将目标 Class、跳转类型（Activity/Fragment/Provider 等）填入 Postcard。
3. **执行拦截器链**：所有已启用的拦截器按优先级顺序执行，可异步处理（内部用 `CountDownLatch` 保证卡片的继续传递）。拦截器调用 `onContinue` 放行，`onInterrupt` 中断并抛出异常。
4. **执行跳转**：`_ARouter.navigation` 根据类型执行实际跳转——Activity 会用 `context.startActivity(intent)`，Fragment 会创建实例并返回，Provider 则从缓存或新建并返回。

### 4. 拦截器机制
- 实现 `IInterceptor` 接口，并用 `@Interceptor(priority = 1)` 标注优先级
- 所有拦截器在 `ARouter.init` 时被加载并排序
- 跳转时逐一回调，支持异步操作（如网络校验），完成后必须调用 `onContinue(card)` 或 `onInterrupt` 让流程继续或终止
- 常用来统一处理**登录检查、权限校验、埋点**等

### 5. 服务发现与依赖注入
- `IProvider` 标记的服务可通过 `@Route` 指定路径或直接通过接口 Class 发现
- `ARouter.getInstance().navigation(HelloService.class)` 可获取实现类实例
- `@Autowired` 注解可在页面或服务中自动注入跳转携带的参数，原理是 ARouter 在编译时生成了注入辅助类，运行时调用 `ARouter.inject(this)` 完成赋值

## 二、ARouter 降级策略

当路由表里找不到目标路径时（如路径不存在、动态下架、线上版本不一致等），就需要降级策略来保证用户体验不崩溃。

### 1. 两种降级入口
- **全局降级服务**：提供一个统一的降级实现，所有丢失路径都会触发。
- **局部降级回调**：在单次 `navigation` 时设置回调，仅对当次跳转生效，优先级高于全局。

### 2. 全局降级：DegradeService
实现 `DegradeService` 接口并添加 `@Route` 注解：
```java
@Route(path = "/service/degrade")
public class DegradeServiceImpl implements DegradeService {
    @Override
    public void onLost(Context context, Postcard postcard) {
        // 统一降级处理，例如跳转到 WebView 降级页、展示错误提示或尝试重定向
        ARouter.getInstance().build("/fallback/error")
               .withString("lostPath", postcard.getPath())
               .navigation();
    }

    @Override
    public void init(Context context) { }
}
```
- 当路由丢失且没有局部回调时，框架会从仓库中查找 `DegradeService` 的唯一实现并调用 `onLost`。
- 必须注意：`DegradeService` 自身的 `@Route` 路径不会被丢失查找触发（框架做了过滤）。

### 3. 局部降级：NavigationCallback
在 `navigation` 时直接传入回调：
```java
ARouter.getInstance().build("/unknown/path")
    .navigation(context, new NavigationCallback() {
        @Override
        public void onFound(Postcard postcard) { }
        @Override
        public void onLost(Postcard postcard) {
            // 当前跳转的专属降级逻辑
            Toast.makeText(context, "页面丢失", Toast.LENGTH_SHORT).show();
        }
        @Override
        public void onArrival(Postcard postcard) { }
    });
```
- `onLost` 被执行后，不会再查找全局 `DegradeService`。
- 适合需要对特定路径做差异化的降级处理场景。

### 4. 降级源码优先级逻辑
在 `LogisticsCenter.completion` 中发现路径丢失时，最终会进入 `_ARouter.navigation` 的错误分支，代码大致逻辑：
```java
if (!postcard.isGreenChannel()) { ... } // 拦截器等
if (callback != null) {
    callback.onLost(postcard);
} else {
    DegradeService degradeService = ARouter.getInstance().navigation(DegradeService.class);
    if (degradeService != null) {
        degradeService.onLost(context, postcard);
    } else {
        // 没有任何降级处理，Debug 下可能 Toast 提示或直接抛出异常
    }
}
```
所以优先级：**局部 NavigationCallback > 全局 DegradeService**。

### 5. 常用降级场景实践

#### 5.1 统一错误页兜底
在全局 `onLost` 中跳转到一个固定的“页面未找到”错误 Activity，并把丢失的路径或参数带给错误页，方便客服定位。

#### 5.2 动态重定向（补路）
某些动态化场景（如 Flutter 容器、RN 页面）路径可能因版本不一致而丢失，可在 `onLost` 中调用服务端接口获取一个新的目标路径，然后通过 `ARouter` 再次跳转：
```java
// 远程映射本地缓存
String newPath = RemoteConfigManager.redirect(postcard.getPath());
if (!TextUtils.isEmpty(newPath)) {
    ARouter.getInstance().build(newPath, postcard.getGroup())
           .with(postcard.getExtras())
           .navigation();
    return;
}
// fallback
ARouter.getInstance().build("/404").navigation();
```

#### 5.3 拦截器内的降级
当拦截器判定需要拦截（如未登录）时，不直接抛出异常，而是：
- 调用 `onInterrupt` 中断当前跳转
- 在拦截中断后，主动发起跳转到登录页，并携带回来后的目标路径，这样就实现了业务层的优雅降级（登录后继续原跳转）

#### 5.4 启动阶段 “闪退降级”
对于启动时必须加载但找不到的服务（如 Provider），可以在获取服务时做空判断，采用 mock 服务或缓存版本，避免因依赖缺失而崩溃。

### 6. 注意事项
- 如果不实现 `DegradeService` 且不设回调，在 Debug 模式下 ARouter 会 Toast 提示路径不存在，Release 下可能静默失败（需查看版本），故务必实现全局降级。
- `DegradeService` 的实现类必须用 `@Route` 标识，且路径不能与正常业务路径混淆。
- 降级逻辑应轻量，避免在 `onLost` 中做耗时操作，以免阻塞主线程。

---

ARouter 的设计通过“编译时生成”+“运行时映射”兼顾了性能与灵活性，而降级策略则是保证应用健壮性的关键一环，合理使用全局与局部降级可以让路由框架在生产环境中更稳定可靠。
