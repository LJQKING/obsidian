Android BLE 分包与合包，本质上是**在MTU（Maximum Transmission Unit，最大传输单元）限制下，为传输大数据而设计的应用层协议**。

### 核心概念：MTU与分包原因

*   **MTU是什么**：BLE每次能传输的数据包最大长度。默认MTU为23字节，除去3字节的协议头部，**实际可用于应用数据的只有20字节**。
*   **为何需要分包**：当你要发送的数据超过20字节（或协商后的MTU-3字节），就必须在发送端拆分成多个小包，在接收端再按顺序合并还原。
*   **优化MTU**：可以通过 `BluetoothGatt.requestMtu(512)` 向BLE设备申请更大的MTU（如512字节），并在 `onMtuChanged` 回调中获取实际协商后的MTU值。MTU越大，分包数量越少，传输效率越高。

### 分包与合包的实现原理

应用层需要自己定义协议来标记包的顺序和总数。常见的两种方式：

*   **头部信息法**：在每个数据包头部添加元数据。例如，用**前2个字节表示总包数，接着2个字节表示当前包号**，后面才是真正的数据。这种方式通用性强，不依赖底层特性。

*   **顺序发送法（隐含顺序）**：发送端按顺序连续发送数据包，接收端按接收顺序依次拼接。这种方式实现简单，但一旦丢包，后续所有包都会错位，可靠性较低。

### 发送端（分包）代码示例

```java
// 假设已通过 requestMtu 和 onMtuChanged 获取到实际的 mtuSize
public List<byte[]> splitData(byte[] data, int mtuSize) {
    List<byte[]> packets = new ArrayList<>();
    // 实际数据载荷大小 = MTU - 4字节头部
    int payloadSize = mtuSize - 4;
    int totalPackets = (int) Math.ceil(data.length / (double) payloadSize);

    for (int i = 0; i < totalPackets; i++) {
        int start = i * payloadSize;
        int length = Math.min(payloadSize, data.length - start);
        
        // 1. 创建数据包：4字节头部 + 数据
        ByteBuffer buffer = ByteBuffer.allocate(4 + length);
        // 写入总包数（2字节）
        buffer.putShort((short) totalPackets);
        // 写入当前包号，从1开始（2字节）
        buffer.putShort((short) (i + 1));
        // 写入实际数据
        buffer.put(data, start, length);
        
        packets.add(buffer.array());
    }
    return packets;
}
```


### 接收端（合包）代码示例

```java
// 使用 Map 缓存不同设备或会话的接收数据
private Map<String, SortedMap<Integer, byte[]>> receiveCache = new HashMap<>();

public void onCharacteristicChanged(BluetoothGattCharacteristic characteristic) {
    byte[] packet = characteristic.getValue();
    if (packet == null || packet.length < 4) return;

    ByteBuffer buffer = ByteBuffer.wrap(packet);
    int totalPackets = buffer.getShort() & 0xFFFF;
    int currentIndex = buffer.getShort() & 0xFFFF;
    byte[] data = new byte[packet.length - 4];
    buffer.get(data);

    String key = characteristic.getDevice().getAddress();
    SortedMap<Integer, byte[]> packetsMap = receiveCache.get(key);
    if (packetsMap == null) {
        packetsMap = new TreeMap<>();
        receiveCache.put(key, packetsMap);
    }
    packetsMap.put(currentIndex, data);

    // 检查是否收齐所有包
    if (packetsMap.size() == totalPackets) {
        // 合并所有数据
        ByteArrayOutputStream outputStream = new ByteArrayOutputStream();
        for (byte[] chunk : packetsMap.values()) {
            outputStream.write(chunk, 0, chunk.length);
        }
        byte[] completeData = outputStream.toByteArray();
        // 处理完整数据...
        receiveCache.remove(key); // 清理缓存
    }
}
```


### 如何确认包发送成功

**关键点**：`gatt.writeCharacteristic()` 返回 `true` 仅表示写入请求被成功提交到蓝牙协议栈**队列**中，**不代表数据已经发送到对方设备**。

真正确认发送成功，需要通过 `BluetoothGattCallback` 的 `onCharacteristicWrite` 回调。

```java
private BluetoothGattCallback gattCallback = new BluetoothGattCallback() {
    @Override
    public void onCharacteristicWrite(BluetoothGatt gatt,
                                      BluetoothGattCharacteristic characteristic,
                                      int status) {
        if (status == BluetoothGatt.GATT_SUCCESS) {
            // 该包已成功发送到对方设备
            Log.d("BLE", "Packet sent successfully");
        } else {
            // 发送失败，需要处理重发等逻辑
            Log.e("BLE", "Packet send failed with status: " + status);
        }
    }
};
```


**注意**：`onCharacteristicWrite` 回调只在写入类型为 **`WRITE_TYPE_DEFAULT`（带响应）** 时触发。如果使用 `WRITE_TYPE_NO_RESPONSE`（无响应），则不会收到此回调。

### 最佳实践建议

1.  **发送队列机制**：维护一个发送队列，在 `onCharacteristicWrite` 回调中收到 `GATT_SUCCESS` 后，再从队列中取出下一个包发送。这能确保每个包都得到确认，避免因快速连续发送导致蓝牙缓冲区溢出。

2.  **包间延时**：即使使用队列，也建议在每包之间添加 **50ms 左右的短暂延时**。

3.  **超时与重传**：为每个发送的包设置超时计时器，如果在规定时间内未收到 `onCharacteristicWrite` 回调，则进行重传。

4.  **区分“发送成功”与“处理成功”**：`onCharacteristicWrite(status = GATT_SUCCESS)` 仅表示数据已送达对端蓝牙模块，不代表对端应用层已处理该数据。如需确认后者，需由对端应用层通过 Notification 或 Indication 返回应用层确认消息。
