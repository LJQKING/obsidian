## 1️⃣ 核心概念

### DataStore vs SharedPreferences

```
┌─────────────────────┬──────────────────┬──────────────────┐
│      特性           │   DataStore      │  SharedPref      │
├─────────────────────┼──────────────────┼──────────────────┤
│ 异步操作            │ ✅ 原生支持       │ ❌ 需手动处理    │
│ 协程友好            │ ✅ Flow API       │ ❌ 回调式        │
│ 类型安全            │ ✅ Proto版本      │ ❌ 限定基本类型  │
│ 事务支持            │ ✅ 原子操作       │ ❌ 不支持        │
│ 性能                │ ✅ 使用Protobuf  │ ❌ 磁盘同步      │
│ 学习曲线            │ ⭕ 中等           │ ✅ 低            │
└─────────────────────┴──────────────────┴──────────────────┘
```

## 3️⃣ 关键代码实现

### 3.1 Repository 层

```kotlin
/**
 * 核心：定义存储key和操作方法
 */
class HomeItemVisibilityRepository(private val context: Context) {
    
    // 获取DataStore实例
    private val dataStore = context.homeDataStore
    
    // 定义key
    companion object {
        private val BANNER_VISIBLE_KEY = booleanPreferencesKey("banner_visible")
        private val RECOMMENDATION_VISIBLE_KEY = booleanPreferencesKey("recommendation_visible")
    }
    
    // 暴露Flow给ViewModel
    val bannerVisibility: Flow<Boolean> = dataStore.data.map { preferences ->
        preferences[BANNER_VISIBLE_KEY] ?: true  // 默认值为true
    }
    
    // 切换操作（suspend函数）
    suspend fun toggleBannerVisibility() {
        dataStore.edit { preferences ->
            val currentValue = preferences[BANNER_VISIBLE_KEY] ?: true
            preferences[BANNER_VISIBLE_KEY] = !currentValue
        }
    }
    
    // 批量设置（原子操作）
    suspend fun setVisibilities(
        bannerVisible: Boolean? = null,
        recommendationVisible: Boolean? = null
    ) {
        dataStore.edit { preferences ->
            bannerVisible?.let { preferences[BANNER_VISIBLE_KEY] = it }
            recommendationVisible?.let { preferences[RECOMMENDATION_VISIBLE_KEY] = it }
        }
    }
}
```

**关键点：**

- ✅ 使用 `booleanPreferencesKey()` 定义类型安全的key
- ✅ 使用 `edit {}` 进行原子操作
- ✅ `map {}` 转换Flow并提供默认值
- ✅ 所有写操作都是 `suspend` 函数

### 3.2 ViewModel 层

```kotlin
/**
 * 核心：转换Flow为StateFlow，提供UI交互方法
 */
class HomeViewModel(
    private val repository: HomeItemVisibilityRepository
) : ViewModel() {
    
    // 关键：Flow → StateFlow 转换
    val bannerVisible: StateFlow<Boolean> = repository.bannerVisibility
        .stateIn(
            scope = viewModelScope,                              // 使用ViewModel的协程作用域
            started = SharingStarted.WhileSubscribed(5000),      // 智能订阅管理
            initialValue = true                                  // 提供初始值
        )
    
    // UI交互方法
    fun toggleBanner() {
        viewModelScope.launch {
            repository.toggleBannerVisibility()  // 自动更新StateFlow
        }
    }
    
    // 批量操作
    fun setVisibilities(
        bannerVisible: Boolean? = null,
        recommendationVisible: Boolean? = null
    ) {
        viewModelScope.launch {
            repository.setVisibilities(
                bannerVisible = bannerVisible,
                recommendationVisible = recommendationVisible
            )
        }
    }
}
```

**关键点：**

- ✅ 使用 `stateIn()` 将Flow转为StateFlow
- ✅ `SharingStarted.WhileSubscribed(5000)` 智能管理订阅生命周期
- ✅ `initialValue = true` 提供初始值，UI能立即显示
- ✅ 所有协程操作都在 `viewModelScope` 中

### 3.3 UI 层（Traditional）

```kotlin
/**
 * 核心：collect StateFlow，响应更新
 */
class HomeFragment : Fragment() {
    
    private lateinit var viewModel: HomeViewModel
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        // 初始化ViewModel
        viewModel = ViewModelProvider(this).get(HomeViewModel::class.java)
        
        // ✅ 最佳实践：使用repeatOnLifecycle防止内存泄漏
        viewLifecycleOwner.lifecycleScope.launch {
            viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.bannerVisible.collect { isVisible ->
                    binding.bannerContainer.visibility = 
                        if (isVisible) View.VISIBLE else View.GONE
                }
            }
        }
        
        // 用户交互
        binding.hideBannerButton.setOnClickListener {
            viewModel.toggleBanner()
        }
    }
}
```

**关键点：**

- ✅ 使用 `repeatOnLifecycle(STARTED)` 生命周期感知
- ✅ 在 `STARTED` 时订阅，`STOPPED` 时取消
- ✅ 防止内存泄漏和不必要的更新

### 3.4 UI 层（Compose）

```kotlin
/**
 * Compose方案

@Composable
fun HomeScreen(
    viewModel: HomeViewModel = viewModel()
) {
    // 关键：collectAsState将StateFlow转为State
    val bannerVisible by viewModel.bannerVisible.collectAsState()
    
    if (bannerVisible) {
        BannerItem(
            onDismiss = { viewModel.toggleBanner() }
```

## 5️⃣ 最佳实践

### ✅ DO（应该做）

|实践|代码示例|
|---|---|
|使用 `repeatOnLifecycle`|`viewLifecycleOwner.repeatOnLifecycle(STARTED)`|
|使用 `stateIn()` 转换|`repository.flow.stateIn(viewModelScope, ...)`|
|批量编辑|`edit { prefs -> ... }` 一次调用|
|默认值处理|`preferences[KEY] ?: defaultValue`|
|类型安全key|`booleanPreferencesKey()`|
|异步操作|所有写操作都是 `suspend` 函数|
|生命周期管理|在 `viewModelScope` 启动协程|

### ❌ DON'T（不应该做）

|错误|原因|
|---|---|
|使用 `lifecycleScope.launch`|不会自动取消，导致泄漏|
|直接订阅多个Flow|重复计算和订阅|
|同步访问DataStore|阻塞Main线程|
|多次调用 `edit`|破坏原子性|
|未处理错误|Flow可能抛出异常|
|使用 `GlobalScope`|协程无限期运行|

## 6️⃣ 常见问题

### Q1: DataStore数据存储在哪里？

```
/data/data/<package_name>/files/datastore/home_preferences.preferences_pb
```

### Q2: 如何清除所有数据？

```kotlin
suspend fun resetAllVisible() {
    context.homeDataStore.edit { it.clear() }
}
```

### Q3: 数据持久化吗？

✅ 是的，使用 `edit {}` 自动写入磁盘，应用重启后恢复。

### Q4: 多进程支持？

❌ 不支持。DataStore不支持跨进程访问。

### Q5: 初始值何时可用？

✅ 使用 `stateIn(..., initialValue = true)` 后立即可用，无需等待首次读取。

### Q6: 如何实现错误处理？

```kotlin
val visibilityState: Flow<Boolean> = repository.bannerVisibility
    .catch { exception ->
        Log.e("DataStore", "Error reading visibility", exception)
        emit(true)  // 默认值
    }
```

### Q7: 并发操作安全吗？

✅ 完全线程安全。DataStore内部使用Mutex保护。

### Q8: 性能如何？

- 读取：O(1) 内存操作
- 写入：异步，不阻塞UI
- 序列化：Protobuf二进制格式，比JSON高效

## 8️⃣ 性能优化要点

### 🚀 优化1：智能订阅

```kotlin
// ✅ 好：WhileSubscribed 在无人订阅时停止
val state = flow.stateIn(
    scope = viewModelScope,
    started = SharingStarted.WhileSubscribed(5000),  // 5秒超时
    initialValue = false
)

// ❌ 不好：Eagerly 一直保持订阅
val state = flow.stateIn(
    scope = viewModelScope,
    started = SharingStarted.Eagerly,
    initialValue = false
)
```

### 🚀 优化2：批量更新

```kotlin
// ✅ 好：一个edit调用，原子操作
suspend fun setVisibilities(...) {
    dataStore.edit { prefs ->
        // 多个赋值
    }
}

// ❌ 不好：多个edit调用，低效且不原子
suspend fun toggleBanner() { dataStore.edit { ... } }
suspend fun toggleRec() { dataStore.edit { ... } }
// ...
```

### 🚀 优化3：避免重复订阅

```kotlin
// ✅ 好：订阅一次StateFlow
val visible by viewModel.bannerVisible.collectAsState()

// ❌ 不好：重复订阅Flow
val flow1 = repository.bannerVisibility.collect { }
val flow2 = repository.bannerVisibility.collect { }
```

### 🚀 优化4：及时取消

```kotlin
// ✅ 好：STARTED时订阅，STOPPED时取消
viewLifecycleOwner.repeatOnLifecycle(Lifecycle.State.STARTED) {
    viewModel.bannerVisible.collect { }
}

// ❌ 不好：无限期订阅
lifecycleScope.launch {
    viewModel.bannerVisible.collect { }
}
```

## 1️⃣2️⃣ 核心要点总结

### 1. **架构**：三层分离（UI → ViewModel → Repository → DataStore）

### 2. **数据流**：Flow → StateFlow → UI State → Recomposition

### 3. **协程**：所有I/O操作异步，在 `viewModelScope` 中启动

### 4. **生命周期**：使用 `repeatOnLifecycle()` 实现感知

### 5. **原子性**：批量操作使用单个 `edit {}` 调用

### 6. **类型安全**：使用 `booleanPreferencesKey()` 定义key

### 7. **性能**：`WhileSubscribed` 智能管理订阅

### 8. **测试**：单元 + UI测试 + 持久化验证
