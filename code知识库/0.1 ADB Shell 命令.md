
## 📱 ADB 基础

### 设备连接 & 授权

```bash
# 列出所有连接设备及状态
adb devices -l

# 无线 ADB 连接
adb connect <IP>:5555

# 指定设备进入 shell
adb -s <serial> shell

# 获取 root 权限并重挂载 /system 为可写
adb root && adb remount

# 等待设备上线后继续执行
adb wait-for-device
```

### 文件传输

```bash
# 推文件到设备
adb push local.apk /data/local/tmp/

# 拉取 ANR 轨迹文件
adb pull /data/anr/traces.txt ./

# 覆盖安装并授予所有权限
adb install -r -g app.apk

# 卸载 APK
adb uninstall com.pkg.name
```

### Activity / Intent / Service 控制

```bash
# 启动 Activity
adb shell am start -n com.pkg/.MainActivity

# 启动 Service
adb shell am startservice -n com.pkg/.MyService

# 发送广播
adb shell am broadcast -a android.intent.action.BOOT_COMPLETED

# 强制停止应用
adb shell am force-stop com.pkg.name
```

## 🔍 Logcat 日志分析

### 基本过滤 (按 Tag / 级别)

```bash
# 带时间戳输出
adb logcat -v time

# 只显示 Error 级别
adb logcat *:E

# 只看 CarService 的 Verbose 及以上
adb logcat -s CarService:V

# 快速定位崩溃/ANR
adb logcat | grep -E "ANR|FATAL"

# 所有 buffer 输出到文件（main/system/events）
adb logcat -b all -v long > log.txt
```

### AAOS 专项 Tag (智能座舱常用)

```bash
# CarService + HAL 客户端
adb logcat -s CarService:V HalClient:V

# VHAL 属性存储层
adb logcat -s VehiclePropertyStore:V

# 默认 VHAL 实现
adb logcat -s DefaultVehicleHal:V

# 车载音频服务
adb logcat -s CarAudioService:V

# 电源管理服务
adb logcat -s CarPowerManagerService:V
```

### 清除 & 缓冲区管理

```bash
# 清空所有 logcat 缓存
adb logcat -c

# 查看 events buffer 中的车辆事件
adb logcat -b events | grep vehicle

# 设置 logcat 缓冲区大小为 64MB
adb logcat -G 64M
```

## 🛠️ Dumpsys 服务诊断

### CarService 状态 (AAOS 核心服务)

```bash
# 输出所有 CarXxxService 状态
adb shell dumpsys car_service

# 单服务精确 dump (CarAudioService)
adb shell dumpsys car_service --services CarAudioService

# 单服务精确 dump (CarPowerManagementService)
adb shell dumpsys car_service --services CarPowerManagementService

# 多区域/多屏状态 (CarOccupantZoneService)
adb shell dumpsys car_service --services CarOccupantZoneService
```

### Activity & Window (界面与任务栈)

```bash
# 当前栈顶 Activity 信息
adb shell dumpsys activity top

# 任务栈详情
adb shell dumpsys activity activities | grep -A5 "TaskRecord"

# 当前焦点窗口
adb shell dumpsys window windows | grep -E "mCurrentFocus|mFocusedApp"

# 多屏幕配置（仪表盘/副屏）
adb shell dumpsys window displays
```

### 内存 & CPU (进程资源分析)

```bash
# 应用内存详情（PSS / RSS）
adb shell dumpsys meminfo com.pkg.name

# 过去 3 小时进程内存统计
adb shell dumpsys procstats --hours 3

# CPU 占用快照
adb shell dumpsys cpuinfo

# 重置并查看电量统计
adb shell dumpsys batterystats --reset && adb shell dumpsys batterystats
```

## 🚗 VHAL 属性 (车辆属性读写)

### 读取车辆属性

```bash
# 读 PERF_VEHICLE_SPEED (0x11600500)，area=0
adb shell cmd car_service get-property-value 289408000 0

# 读 GEAR_SELECTION (0x11600305)
adb shell cmd car_service get-property-value 291504905 0

# 读 HVAC_FAN_SPEED (0x12400104)
adb shell cmd car_service get-property-value 557842692 0

# 写 HVAC_FAN_SPEED = 3
adb shell cmd car_service set-property-value 557842692 i 3 0
```

> **提示：** 属性 ID 可通过 `VehiclePropertyIds.java` (AOSP) 查询，格式为十进制整数。

### VHAL dump & 事件注入

```bash
# 传统 HIDL VHAL 状态 dump (Android 12 及以下)
adb shell dumpsys android.hardware.automotive.vehicle@2.0::IVehicle/default

# AIDL VHAL 状态 dump (Android 13+)
adb shell dumpsys android.hardware.automotive.vehicle.IVehicle/default

# 注入速度事件 25m/s
adb shell cmd car_service inject-vhal-event 0x11600500 25.0 0

# 注入档位事件（8=DRIVE）
adb shell cmd car_service inject-vhal-event 0x11600305 8 0
```

### 系统属性 (getprop / setprop)

```bash
# Android 版本号
adb shell getprop ro.build.version.release

# 产品型号
adb shell getprop ro.product.model

# 过滤所有 car 相关属性
adb shell getprop | grep car

# 开启 HVAC fake 数据（仿真）
adb shell setprop debug.car.hvac_fake_data true
```

## 📊 性能分析 & 调试

### Perfetto / Systrace (系统级 trace)

```bash
# 采集 10s trace，含调度/频率/WM/AM
adb shell perfetto -o /data/misc/perfetto-traces/trace.pb -t 10s sched freq idle am wm

# 拉取 trace 文件（用 ui.perfetto.dev 打开）
adb pull /data/misc/perfetto-traces/trace.pb ./

# 传统 systrace（AOSP tools）
python3 systrace.py --time=10 -o trace.html sched gfx view wm am
```

### 帧率 & 渲染 (Jank / FPS 分析)

```bash
# 渲染帧率、Jank 帧统计
adb shell dumpsys gfxinfo com.pkg.name

# 重置 gfx 统计后重测
adb shell dumpsys gfxinfo com.pkg.name reset

# SurfaceFlinger 各 Layer 延迟
adb shell dumpsys SurfaceFlinger --latency

# 触发 SurfaceFlinger 状态 dump
adb shell service call SurfaceFlinger 1013
```

### 线程 & ANR (ANR 与堆栈分析)

```bash
# 查看最新 ANR 堆栈
adb shell cat /data/anr/anr_*.txt

# 发 SIGQUIT，触发 traces 写入
adb shell kill -3 $(adb shell pidof com.pkg.name)

# 列出应用所有线程
adb shell ps -A -T | grep com.pkg

# 实时 CPU 占用 top（5次）
adb shell top -d 1 -n 5 | head -30
```

## 💡 常用技巧

### 快速脚本组合

**采集完整诊断包：**

```bash
#!/bin/bash
OUTDIR="diag_$(date +%Y%m%d_%H%M%S)"
mkdir -p $OUTDIR

# 采集 logcat
adb logcat -d -v long > $OUTDIR/logcat.txt

# 采集 CarService dump
adb shell dumpsys car_service > $OUTDIR/car_service.txt

# 采集内存快照
adb shell dumpsys meminfo > $OUTDIR/meminfo.txt

# 采集各服务状态
adb shell dumpsys activity > $OUTDIR/activity.txt
adb shell dumpsys window > $OUTDIR/window.txt

echo "诊断包已保存至 $OUTDIR"
```

## 📝 快速查阅

### 问题排查 Checklist

- **应用无法启动？** → `logcat | grep -E "FATAL|Exception"` + `dumpsys activity top`
- **内存泄漏？** → `dumpsys meminfo <pkg>` + `LeakCanary` 或 MAT 分析
- **VHAL 属性读不到？** → `dumpsys android.hardware.automotive.vehicle.IVehicle/default`
- **UI 卡顿 / 掉帧？** → `dumpsys gfxinfo <pkg>` + Perfetto trace
- **ANR / 无响应？** → `/data/anr/anr_*.txt` + `logcat -s` 核心 Tag
- **电源管理问题？** → `dumpsys car_service --services CarPowerManagementService`
