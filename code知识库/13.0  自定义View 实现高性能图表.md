在 Android 中，使用自定义 View 和 `Canvas` 来实现高性能图表是一个非常经典且考验底层绘制功底的场景。要做到“高性能”，核心原则是**减少绘制开销**和**避免内存抖动（GC）**。

以下是实现高性能图表的关键函数、核心优化思路以及一段具体的折线图（Line Chart）代码示例。

### 一、 核心类与关键函数

在开始撸代码之前，你需要熟练掌握以下几个核心组件：

1. **`View` 及其生命周期回调:**
    
    - `onMeasure(widthMeasureSpec, heightMeasureSpec)`: 决定图表的最终宽高。
        
    - `onSizeChanged(w, h, oldw, oldh)`: 当 View 大小发生变化时触发，**这是预计算图表边界、缩放比例的最佳位置**，千万不要在 `onDraw` 里算。
        
    - `onDraw(canvas: Canvas)`: 绘制的灵魂函数。**绝对不能在这个函数里 `new` 任何对象**。
        
2. **`Canvas` (画布):**
    
    - `drawPath(path, paint)`: **高性能核心**。对于折线图、曲线图，使用 `Path` 一次性绘制，比循环调用 `drawLine` 性能高得多。
        
    - `drawLines(pts, paint)`: 绘制散点或独立线段时，使用浮点数组批量绘制。
        
    - `clipRect()`: 如果你的图表支持缩放平移，使用裁剪区域可以避免绘制屏幕外的内容（减少 Overdraw）。
        
3. **`Paint` (画笔):**
    
    - 设置颜色、线宽、抗锯齿（`isAntiAlias = true`）。
        
    - `style = Paint.Style.STROKE` (只描边) 或 `FILL` (填充，常用于面积图)。
        
4. **`Path` (路径):**
    
    - `moveTo(x, y)`: 移动起点。
        
    - `lineTo(x, y)`: 连线。
        
    - `reset()` 或 `rewind()`: 复用 Path 对象时，用来清空上一次的数据。
        

### 二、 高性能折线图具体代码实现 (Kotlin)

这段代码展示了一个基础的、遵循高性能规范的折线图骨架：

Kotlin

```
import android.content.Context
import android.graphics.Canvas
import android.graphics.Color
import android.graphics.Paint
import android.graphics.Path
import android.util.AttributeSet
import android.view.View

class HighPerformanceLineChartView @JvmOverloads constructor(
    context: Context, attrs: AttributeSet? = null, defStyleAttr: Int = 0
) : View(context, attrs, defStyleAttr) {

    // 1. 提前初始化所有 Paint 和 Path 对象，绝不在 onDraw 中创建
    private val linePaint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        color = Color.parseColor("#1E88E5")
        strokeWidth = 5f
        style = Paint.Style.STROKE
        strokeJoin = Paint.Join.ROUND // 圆滑拐角
    }

    private val gridPaint = Paint(Paint.ANTI_ALIAS_FLAG).apply {
        color = Color.parseColor("#E0E0E0")
        strokeWidth = 1f
        style = Paint.Style.STROKE
    }

    private val linePath = Path()
    
    // 模拟数据源 (0.0 到 1.0 之间的值)
    private var dataPoints: List<Float> = emptyList()
    
    // 缓存的点坐标，避免在 onDraw 中动态计算
    private var cachedX = FloatArray(0)
    private var cachedY = FloatArray(0)

    /**
     * 设置数据并刷新图表
     */
    fun setData(data: List<Float>) {
        this.dataPoints = data
        // 重新分配缓存数组大小
        if (cachedX.size != data.size) {
            cachedX = FloatArray(data.size)
            cachedY = FloatArray(data.size)
        }
        calculateCoordinates()
        invalidate() // 触发重绘
    }

    override fun onSizeChanged(w: Int, h: Int, oldw: Int, oldh: Int) {
        super.onSizeChanged(w, h, oldw, oldh)
        // 尺寸改变时，重新计算坐标
        calculateCoordinates()
    }

    /**
     * 关键性能优化：预先计算好所有的像素坐标。
     * 将业务数据 (Data) 映射为屏幕坐标 (Pixels)。
     */
    private fun calculateCoordinates() {
        if (dataPoints.isEmpty() || width == 0 || height == 0) return

        val width = width.toFloat()
        val height = height.toFloat()
        val stepX = width / (dataPoints.size - 1).coerceAtLeast(1)

        // 寻找最大最小值用于归一化（此处假设已知数据在0-1之间，实际场景需动态查找）
        val maxY = 1.0f 
        val minY = 0.0f

        for (i in dataPoints.indices) {
            cachedX[i] = i * stepX
            // 简单的 Y 轴坐标系反转 (Android 中 Y 轴向下)
            val normalizedY = (dataPoints[i] - minY) / (maxY - minY)
            cachedY[i] = height - (normalizedY * height)
        }

        // 构建 Path
        linePath.reset() // 清空历史路径
        if (cachedX.isNotEmpty()) {
            linePath.moveTo(cachedX[0], cachedY[0])
            for (i in 1 until cachedX.size) {
                linePath.lineTo(cachedX[i], cachedY[i])
            }
        }
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)
        
        if (dataPoints.isEmpty()) return

        // 1. 绘制网格线 (可选，视需求而定)
        canvas.drawLine(0f, height.toFloat(), width.toFloat(), height.toFloat(), gridPaint)

        // 2. 高性能绘制折线：直接绘制预先构建好的 Path
        canvas.drawPath(linePath, linePaint)
        
        // 注意：这里没有任何 new 操作，也没有任何复杂的数学计算
    }
}
```

### 三、 决定生死的性能优化法则

如果你的图表数据量达到成千上万（比如股票 K 线图、心电图等），必须严格遵守以下军规：

#### 1. `onDraw` 绝对零分配 (Zero Allocation)

`onDraw` 在每一帧（16ms）都可能被调用。如果在里面执行了 `new Paint()`、`new Path()` 或创建了字符串（如 `"" + value` 用于绘制文本），会瞬间产生大量内存垃圾，触发 GC（垃圾回收）。**GC 会导致主线程暂停，图表就会卡顿。**

- **做法：** 所有对象提升为类属性（全局变量），在 `init` 块或声明时初始化。
    

#### 2. 数据与视图分离 (预计算)

不要在 `onDraw` 里遍历数据并计算坐标 (如 `x = i * step`, `y = height - val`)。

- **做法：** 当数据更新 (`setData`) 或 视图大小改变 (`onSizeChanged`) 时，提前计算好所有的 `x, y` 坐标点，存放在 `FloatArray` 中，或者直接构建好 `Path` 对象。`onDraw` 只负责纯粹的 `Canvas` 绘制指令。
    

#### 3. 硬件加速 (Hardware Acceleration)

Android 默认开启硬件加速（利用 GPU 绘制）。这使得 `drawPath` 等操作极快。但要注意，如果使用了某些不支持硬件加速的 `Paint` API（例如复杂的自定义 `PathEffect` 或者非常大的 `setShadowLayer`），会导致回退到 CPU 绘制。

- **做法：** 尽量使用基础的颜色和线条样式。如果必须使用阴影，考虑将图表层和高亮层分离，仅对小区域关闭硬件加速。
    

#### 4. 屏幕外剔除 (Culling)

如果你的图表支持左右滑动查看（比如通过 `GestureDetector` 和 `Scroller` 控制偏移量）：

- **做法：** 在 `calculateCoordinates` 或 `onDraw` 中，判断点的 X 坐标是否在当前屏幕可视区域内 `[scrollX, scrollX + width]`。对于完全在屏幕左侧或右侧的线条/数据点，直接跳过，不加入 `Path`，不执行 `draw`。
    

构建底层 View 只是图表开发的第一步。你目前是在处理静态的大数据量展示，还是需要实现动态交互（比如双指缩放平移、长按显示十字准星高亮数据点）？
