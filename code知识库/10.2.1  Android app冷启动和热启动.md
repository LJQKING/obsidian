
## 📱 基本概念

### 冷启动 (Cold Start)

应用进程**不存在**或被完全销毁，系统需要从零开始启动应用。

**时间成本最高** ❌

### 热启动 (Warm Start)

应用进程**仍在内存**中，但 Activity 被销毁，需要重新创建。

**时间成本中等** ⚠️

### 温启动 (Lukewarm Start)

应用进程和部分 Activity 仍在内存中。

**时间成本最低** ✅

## 💻 代码级原理

### 冷启动详细流程

```java
// 1️⃣ System 进程调用
// frameworks/base/services/core/java/com/android/server/am/ActivityManagerService.java
startProcessLocked() {
    // 通过 Zygote Socket 请求 fork
    Process.start("com.example.app", ...);
}

// 2️⃣ Zygote fork 并加载 APP
// frameworks/base/core/java/android/os/Zygote.java
forkAndSpecialize() {
    // 系统调用 fork
    pid = nativeFork();
    // 进程继承 Zygote 的预加载资源
    return pid;
}

// 3️⃣ 运行 Application
// frameworks/base/core/java/android/app/ActivityThread.java
main(String[] args) {
    Looper.prepareMainLooper();
    attach(false);  // 连接到 AMS
    Looper.loop();  // 启动消息循环
}

// 4️⃣ 创建 Application 实例
mApplication = mActivityThread.mInstrumentation.newApplication(
    cl, appClass, appContext);
mApplication.onCreate();  // 回调应用初始化

// 5️⃣ 创建 Activity
startActivity(MainActivity.class);
// → onCreate() → onStart() → onResume()
```

### 热启动流程

```java
// Activity 已在内存中被销毁，但进程存活
// 直接在主线程创建新 Activity 实例

// ✓ 跳过了：Zygote fork、Application.onCreate()

Activity activity = new MainActivity();
activity.attach(...);
activity.onCreate(savedInstanceState);  // ← 从这里开始
activity.onStart();
activity.onResume();
```

## ⏱️ 性能数据对比

|阶段|冷启动|热启动|
|---|---|---|
|**进程创建**|1000-1500ms|0ms ✓|
|**Application.onCreate()**|200-500ms|0ms ✓|
|**Activity 创建**|300-800ms|300-400ms|
|**首帧绘制**|1500-3000ms|600-1200ms|
|**完全启动**|**2000-4000ms**|**600-1500ms**|

## 🎯 冷启动优化策略

### 1. 应用启动画面 (Splash 优化)

```xml
<!-- themes.xml -->
<style name="AppTheme">
    <!-- 设置启动窗口背景 (无需加载任何资源) -->
    <item name="android:windowBackground">@drawable/splash</item>
    <item name="android:windowNoTitle">true</item>
</style>
```

```kotlin
// MainActivity.kt
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        // ⚡ 移除 Splash 主题，使用默认主题
        setTheme(R.style.AppTheme)
        super.onCreate(savedInstanceState)
        
        // 真实内容初始化
        setContentView(R.layout.activity_main)
    }
}
```

### 2. 延迟初始化关键流程

```kotlin
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        
        // ✓ 启动路径必需
        initCriticalFeatures()
        
        // ✗ 后台延迟初始化
        lifecycleScope.launch(Dispatchers.Default) {
            Thread.sleep(2000)  // 等待 UI 显示
            initAnalytics()
            initCrashReporting()
            initAdSDK()  // 第三方 SDK
        }
    }
}
```

### 3. 使用 ContentProvider 延迟初始化

```xml
<!-- AndroidManifest.xml -->
<!-- ✗ 坏做法: 在 Manifest 中声明 provider 会阻塞启动 -->
<provider
    android:name="androidx.startup.InitializationProvider"
    android:authorities="${applicationId}.androidx-startup"
    android:exported="false">
    <meta-data
        android:name="com.example.MyInitializer"
        android:value="androidx.startup" />
</provider>
```

### 4. 布局优化

```xml
<!-- ✗ 复杂嵌套布局 -->
<FrameLayout>
    <LinearLayout>
        <LinearLayout>
            <TextView/>
            <ImageView/>
        </LinearLayout>
    </LinearLayout>
</FrameLayout>

<!-- ✓ 扁平化设计 -->
<ConstraintLayout>
    <TextView ... />
    <ImageView ... />
</ConstraintLayout>
```

### 5. 异步加载列表数据

```kotlin
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        
        // ✓ 先显示空列表/骨架屏
        recyclerView.adapter = adapter
        
        // ✗ 不在 onCreate 中加载数据
        // viewModel.loadData()  // 会阻塞主线程
        
        // ✓ 用 lifecycle 在 resumed 后加载
        lifecycleScope.launch {
            lifecycle.repeatOnLifecycle(Lifecycle.State.RESUMED) {
                viewModel.loadData()
            }
        }
    }
}
```

## 🔧 使用 Perfetto 测量启动时间

```bash
# 1. 启动 Perfetto 追踪
adb shell perfetto --config /data/local/tmp/config.textproto -o /data/local/tmp/trace.perfetto-trace

# 2. 清除应用进程（触发冷启动）
adb shell pm clear com.example.app

# 3. 启动应用
adb shell am start -W com.example.app/.MainActivity

# 4. 拉取追踪文件
adb pull /data/local/tmp/trace.perfetto-trace

# 5. 在 ui.perfetto.dev 打开分析
```

**关键指标：**

- `ActivityStart` → `AppStart` (框架事件)
- `ReportFullyDrawn()` (应用报告完全绘制)
- 查看 `Main Thread` (主线程阻塞)
- 查看 `Disk I/O` (文件读取)

## 📊 面试要点

|概念|要点|
|---|---|
|**冷启动**|Zygote fork、Application.onCreate()、进程创建成本高|
|**热启动**|进程存活、直接创建 Activity、成本是冷启动的 30-50%|
|**优化方向**|启动画面、延迟初始化、布局扁平化、异步 I/O|
|**测量工具**|Perfetto、adb shell am start -W、LeakCanary 检查泄漏|
|**ANR 风险**|冷启动 5s 内、热启动 2s 内必须完成主线程工作|
