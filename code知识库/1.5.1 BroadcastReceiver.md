
### 一、BroadcastReceiver 是什么

- [[1.5  BroadcastReceiver 广播详解.md]]  BroadcastReceiver
BroadcastReceiver（广播接收器）是 Android 四大组件之一，是一种**系统全局的监听器**。它用于接收来自系统或其他应用发送的广播消息（即 `Intent`），并在 `onReceive()` 方法中做出响应。

其核心设计思想是**发布-订阅模式**：一方发送广播（发布者），所有已注册且匹配条件的接收者（订阅者）都能收到。系统自身也会发送大量广播来通知各种事件，例如开机完成、网络变化、电量低、App 安装/卸载等。

---

### 二、启动/注册方式的区别

BroadcastReceiver **不存在“启动”的概念**，其核心在于 **“注册”** 。只有注册后，它才能接收到广播。注册方式主要有两种：**静态注册**和**动态注册**。

#### 1. 静态注册（AndroidManifest.xml）

在 `AndroidManifest.xml` 文件中通过 `<receiver>` 标签声明。

*   **生命周期**：**常驻型**。App 安装后即注册到系统，即使应用进程**没有运行**，也能接收到广播并唤醒应用。
*   **典型场景**：监听**系统级事件**，如开机完成 (`BOOT_COMPLETED`)、网络变化等。
*   **关键限制（Android 8.0+）**：大部分**隐式广播**（不指定具体应用包名）的静态注册**将不再生效**。

#### 2. 动态注册（Context.registerReceiver()）

在 Java/Kotlin 代码中调用 `registerReceiver()` 方法完成注册。

*   **生命周期**：**非驻留型**。跟随注册它的组件（如 Activity）的生命周期。组件销毁时，必须调用 `unregisterReceiver()` 注销，否则会导致**内存泄漏**。
*   **典型场景**：在**应用运行时**，灵活监听特定广播，用于更新 UI 或组件间通信。
*   **最佳实践**：建议在 `onResume()` 中注册，在 `onPause()` 中注销，确保组件销毁前必定注销。
*   **优先级**：在有序广播中，**动态注册的接收器优先级高于静态注册的**。

| 特性                    | 静态注册                  | 动态注册                 |
| --------------------- | --------------------- | -------------------- |
| **注册方式**              | `AndroidManifest.xml` | `registerReceiver()` |
| **生命周期**              | 常驻，App 未启动也能接收        | 随组件生命周期，需手动注销        |
| **灵活性**               | 较低，修改需重新安装            | 高，可在运行时动态控制          |
| **Android 8.0+ 隐式广播** | **大部分失效**             | 不受影响                 |
| **典型场景**              | 开机启动、系统事件监听           | 应用内通信、运行时 UI 更新      |

### 三、具体场景代码实现

以下示例演示了静态注册和动态注册两种方式。

#### 1. 静态注册示例（监听网络变化）

**① 自定义 BroadcastReceiver**

```java
public class NetworkReceiver extends BroadcastReceiver {
    @Override
    public void onReceive(Context context, Intent intent) {
        // 注意：此方法运行在主线程，不能执行耗时操作
        ConnectivityManager cm = (ConnectivityManager) context.getSystemService(Context.CONNECTIVITY_SERVICE);
        NetworkInfo info = cm.getActiveNetworkInfo();
        if (info != null && info.isConnected()) {
            Log.d("NetworkReceiver", "网络已连接");
        } else {
            Log.d("NetworkReceiver", "网络已断开");
        }
    }
}
```

**② 在 `AndroidManifest.xml` 中注册**

```xml
<receiver android:name=".NetworkReceiver"
          android:enabled="true"
          android:exported="true"> <!-- 是否允许外部应用发送广播触发它 -->
    <intent-filter>
        <!-- 监听网络变化 -->
        <action android:name="android.net.conn.CONNECTIVITY_CHANGE" />
    </intent-filter>
</receiver>
```

**③ 添加必要权限**

```xml
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE" />
```

#### 2. 动态注册示例（监听自定义广播）

```java
public class MainActivity extends AppCompatActivity {
    private CustomReceiver customReceiver;
    
    @Override
    protected void onResume() {
        super.onResume();
        // 1. 实例化 BroadcastReceiver
        customReceiver = new CustomReceiver();
        // 2. 创建 IntentFilter 并添加要监听的 Action
        IntentFilter filter = new IntentFilter();
        filter.addAction("com.example.MY_CUSTOM_ACTION");
        // 3. 动态注册
        registerReceiver(customReceiver, filter);
    }

    @Override
    protected void onPause() {
        super.onPause();
        // 4. 务必在 onPause 中注销，防止内存泄漏
        if (customReceiver != null) {
            unregisterReceiver(customReceiver);
            customReceiver = null;
        }
    }

    // 发送自定义广播
    public void sendCustomBroadcast(View view) {
        Intent intent = new Intent("com.example.MY_CUSTOM_ACTION");
        intent.putExtra("message", "Hello from MainActivity");
        sendBroadcast(intent); // 发送无序广播
    }

    // 内部类或独立类
    private static class CustomReceiver extends BroadcastReceiver {
        @Override
        public void onReceive(Context context, Intent intent) {
            String msg = intent.getStringExtra("message");
            Log.d("CustomReceiver", "收到广播: " + msg);
        }
    }
}
```

### 四、实现原理

BroadcastReceiver 的运作由 **ActivityManagerService（AMS）** 统一调度，核心流程如下：

#### 1. 注册过程

*   **静态注册**：App 安装时，**PackageManagerService（PMS）** 解析 `AndroidManifest.xml`，将 `<receiver>` 信息注册到 AMS 的 `mReceivers` 列表中。
*   **动态注册**：调用 `registerReceiver()`，通过 Binder 跨进程通信到 AMS。AMS 会生成一个 `IIntentReceiver` 对象（Binder 接口）用于后续通信，并将该接收器信息存入 `mReceiverResolver` 中。

#### 2. 发送与接收过程

*   **发送广播**：调用 `sendBroadcast()`，最终由 AMS 的 `broadcastIntentLocked()` 处理。
*   **匹配接收者**：AMS 从 `mReceiverResolver`（动态注册）和 `mReceivers`（静态注册）中，根据 Intent 的 Action 等信息匹配出所有符合条件的接收者。
*   **分发广播**：
    *   **无序广播**：通过 Handler 消息机制，**并行**将广播分发给所有匹配的接收者。
    *   **有序广播**：**按优先级串行**分发，每个接收者可修改或截断广播。
*   **回调**：AMS 通过 `IIntentReceiver` 这个 Binder 接口跨进程调用目标应用的 `onReceive()` 方法。

### 五、重要补充

*   **广播类型**：
    *   **普通广播**：`sendBroadcast()`，异步、无序、不可被截断。
    *   **有序广播**：`sendOrderedBroadcast()`，同步、有序、可被截断或修改。
    *   **应用内广播（LocalBroadcastManager）**：仅在 App 内部传递，**更安全、高效**，**不支持静态注册**。适用于应用内组件通信，避免数据泄露风险。
*   **耗时操作**：`onReceive()` 方法**默认运行在主线程（UI 线程）**，**不能执行耗时操作**，否则会引发 ANR。
