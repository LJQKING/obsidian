**Handler/Looper 的核心是基于 Linux epoll 的事件循环模型**：

```
┌──────────────────────────────────────────────────┐
│         Thread (如 Main Thread)                  │
│  ┌─────────────────────────────────────────┐    │
│  │ Looper (死循环，epoll 等待事件)          │    │
│  │  ↓                                        │    │
│  │ MessageQueue (优先级队列)                 │    │
│  │  - 插入消息 (按 when 排序)                │    │
│  │  - 取出消息                              │    │
│  │  ↓                                        │    │
│  │ Handler.handleMessage(msg)              │    │
│  └─────────────────────────────────────────┘    │
│                ↑                                 │
│         其他线程 post/send                      │
└──────────────────────────────────────────────────┘
```

**线程本地存储 (ThreadLocal)**：每个线程最多有一个 Looper

```java
// Looper 类的核心实现
public final class Looper {
    static final ThreadLocal<Looper> sThreadLocal = new ThreadLocal<Looper>();
    
    public static Looper getMainLooper() {
        synchronized (Looper.class) {
            return sMainLooper;
        }
    }
    
    public static void prepare() {
        if (sThreadLocal.get() != null) {
            throw new RuntimeException("Only one Looper may be created per thread");
        }
        sThreadLocal.set(new Looper());
    }
    
    public static void loop() {
        final Looper me = myLooper();
        // 死循环，epoll 等待消息
        for (;;) {
            Message msg = queue.next();  // 可能阻塞
            if (msg == null) return;      // quit() 时退出
            msg.target.dispatchMessage(msg);
        }
    }
}
```

#### 1.2 实战场景：车载IVI系统中的多屏异步更新

**场景**：中控屏主线程需要从后台线程获取 CAN 总线数据，异步更新仪表盘

```java
// 1. 创建专用的Handler线程用于CAN总线数据处理
class CANDataThread extends Thread {
    private Handler mHandler;
    private Handler mMainHandler;
    
    public CANDataThread(Handler mainHandler) {
        mMainHandler = mainHandler;
    }
    
    @Override
    public void run() {
        Looper.prepare();
        mHandler = new Handler(Looper.myLooper()) {
            @Override
            public void handleMessage(Message msg) {
                switch (msg.what) {
                    case MSG_READ_CAN_DATA:
                        // 在专用线程中读取CAN数据（不阻塞主线程）
                        CANData data = readCANBusData();
                        
                        // 发回主线程更新UI
                        Message uiMsg = mMainHandler.obtainMessage();
                        uiMsg.what = MSG_UPDATE_DASHBOARD;
                        uiMsg.obj = data;
                        mMainHandler.sendMessage(uiMsg);
                        break;
                }
            }
        };
        Looper.loop();
    }
    
    public void requestCANData() {
        mHandler.sendEmptyMessage(MSG_READ_CAN_DATA);
    }
}

// 2. 在Activity中使用
public class DashboardActivity extends AppCompatActivity {
    private CANDataThread mCANThread;
    private Handler mMainHandler;
    
    private static final int MSG_UPDATE_DASHBOARD = 100;
    
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.dashboard);
        
        // 主线程Handler处理UI更新
        mMainHandler = new Handler(Looper.getMainLooper()) {
            @Override
            public void handleMessage(Message msg) {
                if (msg.what == MSG_UPDATE_DASHBOARD) {
                    CANData data = (CANData) msg.obj;
                    updateDashboardUI(data);
                }
            }
        };
        
        // 启动CAN数据处理线程
        mCANThread = new CANDataThread(mMainHandler);
        mCANThread.start();
        
        // 定时请求CAN数据（每500ms）
        mMainHandler.postDelayed(
            () -> mCANThread.requestCANData(),
            500
        );
    }
    
    @Override
    protected void onDestroy() {
        super.onDestroy();
        mMainHandler.removeCallbacksAndMessages(null);
        mCANThread.quit();
    }
}
```

**MessageQueue 内部结构**：

```java
public final class Message implements Parcelable {
    public int what;              // 消息类型
    public int arg1, arg2;        // 两个整数参数
    public Object obj;            // 对象参数
    public long when;             // 执行时间（延迟的关键）
    public Handler target;        // 处理该消息的Handler
    public Runnable callback;     // 如果用 post(Runnable) 则这里不为空
}
```

**性能注意**：

- ❌ `Handler.post(Runnable)` 会频繁创建 Message 对象 → 改用对象池
- ✅ `Message.obtain()` 从对象池获取，避免频繁GC
- ✅ 延迟消息时用 `postDelayedAtTime()` 替代 `postDelayed()`

### 2. EventBus（发布-订阅模式）

#### 2.1 对比 Handler 的优势

|对比项|Handler|EventBus|
|---|---|---|
|**解耦**|强耦合（需要持有Handler引用）|松耦合（匿名事件）|
|**多接收者**|不便（每个接收者需要各自的Handler）|原生支持|
|**代码复杂度**|中等|低（注解式）|
|**粘性事件**|不支持|支持|
|**性能**|高（系统级）|中（需要反射）|

### 3. LiveData 与 StateFlow（MVVM架构首选）

#### 3.1 车载系统中的 MVVM 应用

```kotlin
// ViewModel 持有数据
class VehicleStatusViewModel : ViewModel() {
    // 实时车速数据
    private val _vehicleSpeed = MutableLiveData<Int>()
    val vehicleSpeed: LiveData<Int> = _vehicleSpeed
    
    // 车门状态（使用 StateFlow 获得更多功能）
    private val _doorStatus = MutableStateFlow<DoorState>(DoorState.CLOSED)
    val doorStatus: StateFlow<DoorState> = _doorStatus.asStateFlow()
    
    // 燃油量（使用 DistinctUntilChanged 避免重复更新）
    private val _fuelLevel = MutableLiveData<Float>()
    val fuelLevel: LiveData<Float> = _fuelLevel.distinctUntilChanged()
    
    init {
        startMonitoringVehicleData()
    }
    
    private fun startMonitoringVehicleData() {
        // 从CAN总线读取数据
        viewModelScope.launch(Dispatchers.Default) {
            while (isActive) {
                val speed = readCANSpeed()
                _vehicleSpeed.postValue(speed)
                
                val door = readCANDoorStatus()
                _doorStatus.value = door
                
                val fuel = readCANFuelLevel()
                _fuelLevel.postValue(fuel)
                
                delay(500)  // 每500ms更新一次
            }
        }
    }
}

// UI 层订阅数据
class DashboardFragment : Fragment() {
    private val viewModel: VehicleStatusViewModel by viewModels()
```

#### 3.2 LiveData vs StateFlow 详细对比

```kotlin
// ========== LiveData ==========
// ✅ 优点
// - 自动感知生命周期（不需要 repeatOnLifecycle）
// - 内存效率高（生命周期 onStop 时自动停止收集）
// - 系统级支持（AAC框架）

// ❌ 缺点
// - 不是 Flow 的真正冷流（需要 value）
// - distinctUntilChanged 需要单独调用
// - 不支持 Flow operators

data class DashboardState(
    val speed: Int = 0,
    val fuel: Float = 100f,
    val temperature: Int = 80
)

class DashboardViewModel : ViewModel() {
    private val _state = MutableLiveData(DashboardState())
    val state: LiveData<DashboardState> = _state
    
    fun updateSpeed(speed: Int) {
        val current = _state.value ?: DashboardState()
        _state.value = current.copy(speed = speed)
    }
}

// ========== StateFlow ==========
// ✅ 优点
// - 完整的 Flow 支持（map, filter, flatMapLatest 等）
// - 真正的冷流（每个订阅者独立）
// - 支持 Flow Operators
// - 与 Coroutines 深度集成

// ❌ 缺点
// - 需要手动处理生命周期（repeatOnLifecycle）
// - 更复杂的学习曲线
// - 不自动停止收集

class DashboardViewModel2 : ViewModel() {
    private val _state = MutableStateFlow(DashboardState())
    val state: StateFlow<DashboardState> = _state.asStateFlow()
    
    // 复杂的数据转换示例
    val speedAlert = state
        .map { it.speed }
        .filter { it > 120 }           // 只有超速时才处理
        .distinctUntilChanged()        // 相同速度不处理
        .flatMapLatest { speed ->      // 针对不同速度执行不同操作
            triggersSpeedAlert(speed)
        }
        .stateIn(viewModelScope, SharingStarted.Lazily, null)
}

// ========== 车载实战选择 ==========
// 1. 简单数据显示 → LiveData
// 2. 复杂流转换 → StateFlow
// 3. 混合项目 → 同时使用，各取所长
```

### 4. Kotlin Flow（冷流与热流）

#### 4.1 Flow vs StateFlow vs SharedFlow

```kotlin
// ========== Flow（冷流）==========
fun getVehicleDataStream(): Flow<VehicleData> {
    return flow {  // 冷流构建器
        while (currentCoroutineContext().isActive) {
            val data = readVehicleData()
            emit(data)
            delay(500)
        }
    }
}

// 冷流特性：每个collector 独立执行流程
val flow = getVehicleDataStream()

// collector1 启动新的flow执行
flow.collect { data1 -> 
    println("Collector1: $data1")
}

// collector2 再启动一次独立的flow执行
flow.collect { data2 -> 
    println("Collector2: $data2")
}

// ========== StateFlow（热流）==========
// 用于状态管理，总是有最新值
class VehicleStatusViewModel : ViewModel() {
    private val _speedState = MutableStateFlow(0)
    val speedState = _speedState.asStateFlow()
    
    init {
        viewModelScope.launch {
            readVehicleSpeedContinuously().collect { speed ->
                _speedState.value = speed
            }
        }
    }
}

// 特性1：新订阅者立即收到当前最新值
val viewModel = VehicleStatusViewModel()
viewModel.speedState.collect { speed ->
    println("Current speed: $speed")  // 立即收到最新值
}

// 特性2：所有 collectors 共享同一个数据源
viewModel.speedState.collect { speed1 -> }  // collector1
viewModel.speedState.collect { speed2 -> }  // collector2
// 同一个数据源的更新，两个collector都会收到

// ========== SharedFlow（更灵活的热流）==========
// 用于事件广播（如导航事件、错误事件等）
class NavigationManager {
    private val _navigationEvent = MutableSharedFlow<NavigationEvent>(
        replay = 1,           // 保留1个历史事件
        extraBufferCapacity = 10,  // 额外缓冲容量
        onBufferOverflow = BufferOverflow.DROP_OLDEST
    )
    val navigationEvent = _navigationEvent.asSharedFlow()
    
    suspend fun navigate(event: NavigationEvent) {
        _navigationEvent.emit(event)
    }
}

// 应用：多屏导航同步
class DashboardScreen(private val navManager: NavigationManager) {
    fun onCreate() {
        lifecycleScope.launch {
            navManager.navigationEvent.collect { event ->
                when (event) {
                    is NavigationEvent.ToHomeScreen -> goHome()
                    is NavigationEvent.ToSettingsScreen -> goSettings()
                }
            }
        }
    }
}

// ========== 对比总结 ==========
// | 特性 | Flow | StateFlow | SharedFlow |
// |-----|------|-----------|------------|
// | 冷/热 | 冷 | 热 | 热 |
// | 有初始值 | ❌ | ✅ | ❌ |
// | 多subscribers | 各自执行 | 共享执行 | 共享执行 |
// | 重放 | ❌ | ✅(1个) | ✅(可配) |
// | 背压 | ✅ | ❌ | 🔧可配 |
```

```kotlin
class GPSViewModel : ViewModel() {
    
    // 模拟GPS数据流
    private fun getGPSLocationFlow(): Flow<Location> {
        return flow {
            while (isActive) {
                val location = readGPSData()
                emit(location)
                delay(1000)  // 每秒一次
            }
        }
    }
    
    // 场景1：去重（相同位置只处理一次）
    val uniqueLocations = getGPSLocationFlow()
        .distinctUntilChanged { old, new ->
            old.distance(new) < 5  // 5米内认为是同一位置
        }
    
    // 场景2：节流（每5秒最多处理一次）
    val throttledLocations = getGPSLocationFlow()
        .sample(5000)  // 每5秒采样一次
    
    // 场景3：缓冲后批量处理
    val batchedLocations = getGPSLocationFlow()
        .buffer(capacity = 10)  // 缓冲10个位置
        .collect { locations ->
            updateMapBatch(locations)
        }
    
    // 场景4：组合多个数据流
    val combinedDrivingData = combine(
        getGPSLocationFlow(),
        getSpeedFlow(),
        getHeadingFlow()
    ) { location, speed, heading ->
        DrivingData(location, speed, heading)
    }
    
    // 场景5：超时处理
    val locationWithTimeout = getGPSLocationFlow()
        .timeout(5000)  // 5秒无数据抛异常
        .catch { ex ->
            emit(Location.UNKNOWN)
        }
    
    // 场景6：flatMapLatest（导航重新规划）
    val navigationRoute = getGPSLocationFlow()
        .flatMapLatest { location ->
            getNavigationRoute(location)  // 每个新位置重新规划路线
        }
```

### 1. Binder 机制（Android 的灵魂）

#### 1.1 Binder 的工作原理

**背景**：Android 中每个应用都是独立进程，进程间内存隔离。Binder 是一个跨进程通信机制。

```
┌─────────────────────────────────────────────────────────────┐
│                     内核 (Kernel Space)                      │
│  ┌────────────────────────────────────────────────────────┐ │
│  │           Binder Driver (binder.c)                     │ │
│  │  - 维护所有 Binder 对象的映射表                          │ │
│  │  - 处理跨进程通信                                      │ │
│  │  - 引用计数管理                                        │ │
│  └────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
          ↑                                      ↑
          │                                      │
   ┌──────┴──────────────────┐         ┌────────┴──────────────┐
   │  进程A (Server)          │         │  进程B (Client)       │
   │ ┌────────────────────┐  │         │ ┌─────────────────┐  │
   │ │ ServiceManager    │  │         │ │ Client Code   │  │
   │ │ (注册/查询服务)     │  │         │ │               │  │
   │ │                  │  │         │ │ Proxy          │  │
   │ │ Binder Service   │◄─┼─────────┼─┤ (IBinder接口)  │  │
   │ │ (真实实现)        │  │         │ │               │  │
   │ └────────────────────┘  │         │ └─────────────────┘  │
   └────────────────────────┘         └────────────────────┘
```

```java
// ========== 基于 Messenger 的音乐服务 ==========
public class MessengerMusicService extends Service {
    
    public static final int MSG_PLAY = 1;
    public static final int MSG_PAUSE = 2;
    public static final int MSG_STOP = 3;
    public static final int MSG_GET_STATUS = 4;
    
    private MediaPlayer mMediaPlayer;
    private boolean mIsPlaying = false;
    
    // Handler 处理客户端请求
    private Handler mHandler = new Handler(Looper.getMainLooper()) {
        @Override
        public void handleMessage(Message msg) {
            switch (msg.what) {
                case MSG_PLAY: {
                    String path = msg.getData().getString("path");
                    playMusic(path);
                    
                    // 回复客户端
                    if (msg.replyTo != null) {
                        try {
                            Message reply = Message.obtain(
                                null, 
                                100,  // 回复类型
                                mIsPlaying ? 1 : 0  // 状态
                            );
                            msg.replyTo.send(reply);
                        } catch (RemoteException e) {
                            Log.e("Messenger", "Failed to reply", e);
                        }
                    }
                    break;
                }
                case MSG_PAUSE:
                    pauseMusic();
                    break;
                case MSG_STOP:
                    stopMusic();
                    break;
                case MSG_GET_STATUS: {
                    // 返回当前状态给客户端
                    if (msg.replyTo != null) {
                        try {
                            Message reply = Message.obtain();
                            reply.what = 101;
                            reply.arg1 = mIsPlaying ? 1 : 0;
                            msg.replyTo.send(reply);
                        } catch (RemoteException e) {
                            e.printStackTrace();
                        }
                    }
                    break;
                }
            }
        }
    };
    
    private Messenger mMessenger = new Messenger(mHandler);
    
    @Override
    public IBinder onBind(Intent intent) {
        return mMessenger.getBinder();
    }
    
    private void playMusic(String path) {
        try {
            mMediaPlayer = new MediaPlayer();
            mMediaPlayer.setDataSource(path);
            mMediaPlayer.start();
            mIsPlaying = true;
        } catch (Exception e) {
            Log.e("Messenger", "Failed to play", e);
        }
    }
    
    private void pauseMusic() {
        if (mMediaPlayer != null && mIsPlaying) {
            mMediaPlayer.pause();
            mIsPlaying = false;
        }
    }
    
    private void stopMusic() {
        if (mMediaPlayer != null) {
            mMediaPlayer.stop();
            mMediaPlayer.release();
            mMediaPlayer = null;
            mIsPlaying = false;
        }
    }
}
```

## 总结表格

|技术|场景|优点|缺点|IPC支持|
|---|---|---|---|---|
|**Handler**|主线程消息分发|简单、系统级|强耦合|❌|
|**EventBus**|多模块通信|解耦、支持粘性|反射开销|❌|
|**LiveData**|MVVM UI绑定|生命周期感知|功能单一|❌|
|**StateFlow**|复杂流转换|Flow operator完整|手动生命周期|❌|
|**AIDL**|跨进程通信|高性能、类型安全|复杂、需编译生成|✅|
|**Binder**|Android系统通信|最高效|难度大、容易死锁|✅|
|**ContentProvider**|数据共享|权限控制、观察者|相对复杂|✅|
|**Messenger**|简单跨进程|简化的IPC|性能低于AIDL|✅|
|**Socket**|Native通信|通用、高效|需要自定义协议|✅|
